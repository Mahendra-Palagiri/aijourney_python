## 🧠 Core Concept 1 — What Is NLP?

**NLP means Natural Language Processing.**

It is the area of AI that deals with human language.

Examples of language data:

```text
emails
reviews
chat messages
documents
search queries
support tickets
contracts
medical notes
news articles
```

The goal is to make machines work with language in useful ways.

Typical NLP tasks include:

- Sentiment analysis
- Spam detection
- Text classification
- Document search
- Summarization
- Question answering
- Translation
- Chatbot responses
- Extracting names, dates, amounts, or entities
- Finding similar documents

Key idea:

```text
NLP is not just “chatbots.”
NLP is any AI/ML work where the input or output is language.
```

## 🧠 Core Concept 2 — Why Text Is Different

In tabular ML, our data already looks numerical or structured:

```text
age = 42
income = 85000
rooms = 4
has_garage = 1
```

In image ML, pixels are already numbers:

```text
pixel intensity = 0 to 255
```

But text is different:

```text
"The movie was surprisingly good."
```

A machine does not automatically understand:

- `movie`
- `surprisingly`
- `good`
- tone
- context
- relationships between words
- sarcasm

To a computer, raw text initially starts as characters:

```text
"T" "h" "e" " " "m" "o" "v" "i" "e" ...
```

Before ML can use text, we need to convert it into a numerical form.

That process is called **text representation**.

---

## 🧠 Core Concept 3 — The Central NLP Problem

The central question in NLP is:

```text
How do we turn language into numbers while preserving useful meaning?
```

Bad representation loses meaning.

Better representation keeps more useful signal.

Example:

```text
Text A: "The food was excellent."
Text B: "The food was terrible."
```

These two sentences are structurally similar.

But their meaning is opposite.

If our representation only focuses on shared words like:

```text
the, food, was
```

then the model may miss the real difference:

```text
excellent vs terrible
```

So representation matters.

---

## 🧠 Core Concept 4 — Text Must Become Features

This connects directly to earlier ML weeks.

Every model needs input features.

For tabular data:

```text
[age, income, rooms]
```

For images:

```text
[pixel_1, pixel_2, pixel_3, ...]
```

For text, we need to create something like:

```text
[word_count_good, word_count_bad, word_count_price, ...]
```

Or later, with embeddings:

```text
[0.12, -0.44, 0.78, 0.31, ...]
```

That means text representation is a form of **feature engineering**.

In classical NLP, we often create features using:

```text
bag-of-words
TF-IDF
n-grams
```

In modern NLP, we often use learned representations:

```text
embeddings
transformers
LLMs
```

But the principle is the same:

```text
text → numbers → model/search/evaluation
```

## 🧠 Core Concept 5 — Important NLP Vocabulary

### Document

A **document** is one unit of text.

It does not have to mean a long PDF.

A document could be:

```text
one review
one email
one paragraph
one support ticket
one resume
one web page
```

Example:

```text
Document 1: "The food was good."
Document 2: "The service was slow."
Document 3: "The food was excellent."
```

---

### Corpus

A **corpus** is a collection of documents.

Examples:

```text
corpus = all reviews
corpus = all emails
corpus = all support tickets
```

Example corpus:

```text
1. "The food was good."
2. "The service was slow."
3. "The food was excellent."
```

---

### Token

A **token** is a piece of text after splitting.

Often, a token is close to a word.

```text
"The food was good"
→ ["The", "food", "was", "good"]
```

But tokens are not always full words.

Modern LLM tokenizers may split words into pieces:

```text
"unbelievable"
→ ["un", "believ", "able"]
```

For now, we can use this simple mental model:

```text
token ≈ word or word-piece
```

---

### Vocabulary

A **vocabulary** is the set of unique tokens the system knows from the corpus.

Example corpus:

```text
"The food was good"
"The food was excellent"
```

Vocabulary:

```text
["the", "food", "was", "good", "excellent"]
```

This vocabulary becomes important when we build numerical features.

## 🧠 Core Concept 6 — Why Simple Word IDs Are Not Enough

A tempting idea is:

```text
apple = 1
banana = 2
car = 3
movie = 4
```

But this is dangerous.

Why?

Because numbers imply relationships.

If we write:

```text
apple = 1
banana = 2
car = 3
```

A model may treat `banana` as numerically closer to `apple` than `car` is.

But that number distance does not mean true semantic distance.

The number is just an ID.

So we need better ways to represent text.

That is why NLP uses methods like:

```text
bag-of-words
TF-IDF
embeddings
```

Each method tries to represent text more usefully.

---

## 🧠 Core Concept 7 — NLP Is Not Magic Understanding

We should keep the same discipline from Week 12.

In Week 12, the more complex image-aware model did not automatically win. The baseline won based on evidence.

The same principle applies in NLP.

A fancy LLM or embedding model is not automatically better for every task.

We still ask:

```text
What is the task?
What is the input?
What is the output?
What baseline should we compare against?
What metric matters?
What errors are acceptable?
What errors are risky?
```

For example, a simple TF-IDF model may be enough for:

```text
basic document search
keyword-heavy classification
spam filtering
support ticket routing
```

An embedding or LLM-based approach may help more for:

```text
semantic search
question answering
paraphrase matching
RAG
summarization
```

But we do not assume.

We evaluate.


NLP follows the same pattern:

```text
text → text representation → model/search system → output → evaluation
```

The hard part is that text starts as messy human language.

So Week 13 is mostly about this bridge:

```text
language → numerical meaning
```

## 📝 Concept Check

### Questions

1. Why can’t we feed raw text directly into most traditional ML models?
2. What is the difference between a document and a corpus?
3. What is a token?
4. Why is assigning each word a random ID not a good text representation?
5. Why should we still compare against simple baselines in NLP?
6. What is the main bridge Week 13 is trying to build?

---

### Answer Key

1. Most traditional ML models require numerical input. Raw text starts as characters or strings, so we need to convert it into numerical features before a model can use it.

2. A document is one unit of text, such as one review, email, paragraph, or support ticket. A corpus is a collection of documents.

3. A token is a piece of text after splitting. It is often close to a word, but it can also be a word-piece depending on the tokenizer.

4. Random word IDs are not good because the numbers create fake numerical relationships. For example, if `apple = 1`, `banana = 2`, and `car = 3`, the model may treat those distances as meaningful even though the IDs are arbitrary.

5. We compare against simple baselines because complexity does not guarantee better performance. A simple TF-IDF or bag-of-words baseline may outperform a more complex NLP approach for some tasks.

6. Week 13 is building the bridge from human language to numerical representation so that we can use text in ML models, search systems, embeddings, LLM workflows, and RAG systems.
