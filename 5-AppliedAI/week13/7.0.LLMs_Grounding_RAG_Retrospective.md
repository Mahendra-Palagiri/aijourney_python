# 🧠 4. Where LLMs Fit in NLP

Earlier NLP systems were usually designed for a specific task, such as sentiment classification, spam detection, support-ticket routing, or document search. An LLM is more general and can perform question answering, summarization, classification, extraction, rewriting, translation, conversation, and code generation.

The basic operation of a language model is:

```text
input text
→ predict likely next tokens
→ continue generating tokens
→ produce an output
```

An LLM does not retrieve verified facts automatically. It generates text from patterns learned during training and from context supplied at runtime.

```text
language model → generates plausible language
retrieval system → finds information from a collection
```

A response can sound confident and fluent without being factually correct.

## 💬 4.1 Prompting

A prompt gives the model instructions and input. It tells the model what task to perform, what information to process, and how the result should be formatted.

```text
Classify the support ticket using exactly one category:
delivery, refund, billing, or product defect.

Return only the category.

Ticket:
"My package arrived late, and the item inside was damaged."
```

Prompting controls the task and expected behavior, but prompting alone does not guarantee factual accuracy.

## 📚 4.2 Grounding

**Grounding** means giving the model relevant source information and asking it to base its answer on that information.

```text
question
+ relevant source information
→ language model
→ answer based on the supplied source
```

Example context:

```text
Return Policy:
Items may be returned within 30 days of purchase.
The item must be unused and include the original packaging.
Refunds are issued to the original payment method.
```

Grounded question:

```text
Using only the return policy above, answer:
"Can I return an unused item after 20 days?"
```

Grounding improves traceability because we can inspect the evidence used to produce the answer.

# 🔎 5. Retrieval-Augmented Generation

RAG combines two stages:

```text
retrieval + generation
```

- **Retrieval** finds relevant source material.
- **Generation** uses that material to produce a useful answer.

A complete workflow is:

```text
1. Receive the user question
2. Convert the question into an embedding
3. Retrieve the most relevant document chunks
4. Build a prompt containing the question and context
5. Ask the LLM to answer using that context
6. Return the answer, ideally with source references
```

## 🧩 5.1 RAG Components

| Component | Responsibility |
|---|---|
| Knowledge base | Holds source documents |
| Chunking process | Divides documents into searchable units |
| Embedding model | Converts chunks and queries into vectors |
| Vector store or index | Stores and searches document vectors |
| Retriever | Selects top matching chunks |
| Prompt builder | Combines instructions, context, and question |
| Language model | Generates the final answer |
| Evaluation process | Checks retrieval and answer quality |

A failure in an early stage flows into later stages:

```text
poor documents
→ poor chunks
→ poor retrieval
→ weak context
→ weak answer
```

## 📝 5.2 Constructing the Grounded Prompt

```text
You are a customer-support assistant.

Answer the question using only the supplied context.

If the context does not contain the answer, say:
"I do not have enough information to answer."

Context:
Items may be returned within 30 days of purchase.
The item must be unused and include its original packaging.

Question:
Can I return an unused item after 20 days?
```

This prompt contains a task instruction, grounding rule, abstention rule, retrieved context, and user question. The abstention rule allows the model to acknowledge insufficient evidence.

# 🧪 6. Worked RAG Example

Suppose the knowledge base contains:

```text
D1: Track your shipment from the order-status page.
D2: Items may be returned within 30 days for a refund.
D3: Duplicate charges should be reported to the billing team.
D4: Passwords can be reset from the account-recovery page.
```

The user asks:

```text
"I bought something two weeks ago and have not used it.
Can I send it back?"
```

Illustrative retrieval ranking:

| Rank | Chunk | Similarity |
|---:|---|---:|
| 1 | D2 — Return within 30 days if unused | 0.89 |
| 2 | D1 — Track a shipment | 0.38 |
| 3 | D3 — Report duplicate charges | 0.22 |

D2 is supplied to the LLM as context. A grounded response might be:

```text
Yes. The item was purchased within the 30-day return
period and is unused, so it is eligible for return.
```

The retriever found the evidence. The language model converted the evidence into a direct answer.

# ⚠️ 7. RAG Does Not Eliminate Hallucinations

A **hallucination** is generated information that is unsupported, incorrect, or invented. RAG can reduce hallucination risk by providing evidence, but it cannot eliminate the risk.

The model might ignore context, misinterpret it, combine unrelated chunks, add unsupported details, answer despite insufficient information, or use outdated sources.

```text
retrieved context ≠ guaranteed correct answer
```

## 🚧 7.1 Common RAG Failure Points

- **Poor sources:** the knowledge base is incomplete, inaccurate, or outdated.
- **Poor chunking:** chunks mix topics or lose necessary context.
- **Retrieval failure:** the correct document is absent from top-k.
- **Context overload:** too many chunks introduce noise or conflict.
- **Ambiguous questions:** retrieval follows the wrong interpretation.
- **Unsupported generation:** the model adds claims absent from context.
- **Conflicting sources:** documents differ by date, region, or policy.

A reliable system must identify which stage produced the failure.

# 📊 8. Evaluating a RAG System

A RAG system should be evaluated at three levels.

## 🔍 8.1 Retrieval Evaluation

Retrieval evaluation asks: **Did the system find the correct evidence?**

Checks include whether a relevant chunk was retrieved, how highly it ranked, whether irrelevant chunks appeared above it, and whether metadata filters selected the correct product, region, or date.

Possible metrics include Precision@k, Recall@k, and Mean Reciprocal Rank.

## ✍️ 8.2 Generation Evaluation

Generation evaluation asks: **Did the answer use the evidence correctly?**

We inspect correctness, relevance, completeness, groundedness, unsupported claims, clarity, appropriate abstention, and source attribution.

## 🔗 8.3 End-to-End Evaluation

End-to-end evaluation asks: **Did the complete system help the user correctly and safely?**

A useful evaluation set contains representative questions, expected sources, expected answers or key facts, difficult cases, and questions with no available answer. Missing-answer questions test whether the system abstains instead of inventing information.

# 🛡️ 9. Responsible NLP

Applied NLP systems can affect real decisions, so technical performance is not the only concern.

## 🎭 9.1 Bias

Training data, documents, labels, and prompts may contain unfair patterns. We should check whether performance differs across groups, languages, or dialects and whether labeling rules are consistent.

## 🔐 9.2 Privacy

Documents and prompts may contain names, email addresses, financial or health information, internal data, or confidential conversations. Sensitive data should not be embedded, logged, retrieved, or sent to a model without appropriate controls.

## 📅 9.3 Outdated Information

A semantically relevant document may no longer be valid. Dates, versions, status metadata, expiration rules, and removal of obsolete content help control this risk.

## 🎯 9.4 Overconfidence

A fluent answer can appear more reliable than it is. Responsible systems should cite sources where appropriate, distinguish evidence from inference, allow abstention, and escalate uncertain or high-risk cases.

## 🧨 9.5 Untrusted Retrieved Content

Retrieved documents may contain malicious or misleading instructions. Retrieved text should be treated as evidence, not as authority that can override system rules.

# 🔄 10. Classical NLP and Modern NLP

| Approach | Representation | Strength | Limitation |
|---|---|---|---|
| Bag-of-words | Word counts | Simple and interpretable | Loses order and meaning |
| TF-IDF | Weighted word counts | Strong classical baseline | Depends on word overlap |
| Embeddings | Dense semantic vectors | Captures similarity of meaning | Similarity is not guaranteed relevance |
| Semantic search | Ranked embedding matches | Finds paraphrases | Can retrieve plausible but incorrect context |
| RAG | Retrieval plus generation | Produces grounded answers | Can fail during retrieval or generation |

Newer methods do not automatically replace older methods. Exact terms may favor keyword or TF-IDF methods, while natural-language questions and paraphrases may favor embeddings and RAG. The choice must be evaluated on the actual task.

### 13.2 Answer Key

1. An LLM is a general language-generation component that can perform many NLP tasks from instructions and context, but it does not automatically retrieve or verify facts.
2. Prompting defines the task and desired behavior. Grounding supplies source information that the model should use as evidence.
3. RAG stands for Retrieval-Augmented Generation.
4. Retrieval finds relevant source material; generation uses that material to produce an answer.
5. The retriever identifies and ranks document chunks that may contain the evidence needed for the question.
6. The language model interprets the retrieved context and expresses it as a useful natural-language answer.
7. An abstention rule lets the model state that evidence is insufficient instead of inventing an answer.
8. RAG supplies relevant evidence, but the model can still misread, ignore, or add unsupported information to that evidence.
9. A retrieval failure occurs when the correct document is absent from top-k or an irrelevant document ranks above it.
10. A generation failure occurs when the correct context is retrieved but the model produces an unsupported or incorrect claim.
11. Separate evaluation identifies whether a bad final answer came from missing evidence or incorrect use of available evidence.
12. No-answer questions test whether the system can recognize insufficient evidence and abstain.
13. Metadata can restrict results by product, region, language, date, status, or other known constraints.
14. Sensitive information may be exposed through documents, embeddings, logs, retrieved context, or model prompts.
15. Retrieved documents may contain malicious or misleading instructions and must not override trusted system rules.
16. Keyword search may be better for exact error codes, identifiers, names, dates, or required phrases.
17. The progression is raw language → tokens → numerical representation → classification or similarity → retrieval → grounded generation → evaluation.
18. Do not assume complexity is better; compare approaches and trust evaluated behavior.
