# 🔎 4. From Similarity to Search

Search begins with an information need expressed as a query:

```text
"How can I send back an item?"
```

Suppose our knowledge base contains:

```text
Document A: "Track the delivery status of your order."
Document B: "Refunds are available within 30 days of purchase."
Document C: "Update the payment method on your account."
```

A useful search system should rank Document B highest because returning an item and receiving a refund are closely related.

## 🔤 4.1 Keyword Search

Keyword search relies heavily on exact words or closely related text patterns.

For the query:

```text
"How can I send back an item?"
```

a keyword system may look for terms such as:

```text
send
back
item
```

Document B uses different words:

```text
refunds
purchase
```

The document may be relevant, but exact word overlap is weak. A keyword system can therefore miss it or rank it too low.

Keyword search is still valuable. It often performs well when exact terms matter:

- Product codes
- Error messages
- Names
- Dates
- Legal phrases
- Domain-specific terminology

If a user searches for error code `PAY-403`, exact matching may be more reliable than semantic interpretation.

## 🧠 4.2 Semantic Search

Semantic search compares meaning rather than depending only on exact wording.

```text
"send back an item"
≈
"request a refund"
```

An embedding model converts the query and documents into vectors. Texts with related meanings should point in similar directions, producing higher cosine-similarity scores.

Illustrative scores might be:

| Document | Cosine Similarity |
|---|---:|
| Refunds are available within 30 days | 0.82 |
| Track the delivery status of your order | 0.46 |
| Update your payment method | 0.21 |

These numbers are examples, not universal thresholds. Scores depend on the embedding model, text, and domain.

## ⚖️ 4.3 Keyword, Semantic, and Hybrid Search

| Approach | Main Signal | Often Strong For | Common Weakness |
|---|---|---|---|
| Keyword search | Exact term overlap | Codes, names, rare terms, exact phrases | May miss paraphrases and synonyms |
| Semantic search | Meaning-based vector similarity | Natural-language questions and paraphrases | May retrieve conceptually similar but incorrect text |
| Hybrid search | Keyword and semantic signals | Queries needing both exact and conceptual matching | Requires a ranking strategy |

Semantic search is not automatically better. The correct approach depends on the retrieval task and must be evaluated.

# 🧭 5. The Retrieval Workflow

A basic semantic-search system follows this sequence:

```text
prepare documents
→ split documents into searchable units
→ create document embeddings
→ store text, metadata, and vectors

receive user query
→ create query embedding
→ compare query with document vectors
→ rank by similarity
→ return top-k results
```

Document processing normally happens before the user searches. Query embedding and ranking happen when the query arrives.

## 📄 5.1 Queries, Documents, and Chunks

A **query** expresses what the user wants to find.

A **document** is an item in the searchable collection. It might be an FAQ, support article, paragraph, or product description.

Long documents are often divided into **chunks** because one vector for an entire document may combine several unrelated topics.

Consider a long support article containing:

```text
shipping instructions
refund policy
billing corrections
account deletion
```

One embedding for the whole article may represent all four topics vaguely. Smaller chunks allow the refund section to match a refund query directly.

Chunking introduces a tradeoff:

```text
chunks too large
→ mixed topics and less precise matches

chunks too small
→ missing context and fragmented meaning
```

A good chunk should be focused enough to retrieve accurately and complete enough to remain understandable.

## 🔢 5.2 Query and Document Embeddings

All comparable vectors must come from the same compatible embedding model.

```text
query text    → embedding model → query vector
document text → embedding model → document vector
```

Document embeddings are usually calculated once and stored. A new query embedding is calculated at search time.

If documents change, the affected embeddings must be regenerated. If the embedding model changes, the collection generally must be re-embedded so query and document vectors remain compatible.

## 📐 5.3 Ranking by Similarity

The query vector is compared with every candidate document vector—or with an efficient vector index in a larger system.

```text
query vector
→ cosine similarity with candidates
→ similarity scores
→ descending sort
→ ranked results
```

The highest score means the vector directions are most similar. It does not prove that the document is correct, sufficient, current, or safe to use.

## 🏆 5.4 Top-k Retrieval

`k` is the number of results returned.

```text
top-1 → return the highest-ranked result
top-3 → return the three highest-ranked results
top-5 → return the five highest-ranked results
```

A small `k` is focused but may omit useful context. A large `k` improves coverage but may introduce irrelevant material.

The correct value is an evaluation decision, not a universal constant.

## 🏷️ 5.5 Metadata Filters

Vectors capture semantic similarity, while metadata can enforce known constraints.

Example metadata:

```text
language = "English"
product = "mobile_app"
document_status = "current"
region = "United States"
```

A search system might first filter to current U.S. mobile-app documents and then rank the remaining candidates semantically. This prevents a highly similar but obsolete or out-of-region document from being returned.

# 🧪 6. Worked Retrieval Example

Assume our searchable FAQ collection contains:

| ID | Text |
|---|---|
| D1 | Track your shipment using the order-status page. |
| D2 | Items may be returned within 30 days for a refund. |
| D3 | Update an expired credit card in payment settings. |
| D4 | Reset your password from the account recovery page. |
| D5 | Exchange a damaged product by contacting support. |

The user asks:

```text
"How do I get my money back after sending something back?"
```

After embedding the query and documents, suppose we obtain:

| Rank | Document | Similarity |
|---:|---|---:|
| 1 | D2 — Items may be returned within 30 days for a refund. | 0.88 |
| 2 | D5 — Exchange a damaged product by contacting support. | 0.57 |
| 3 | D1 — Track your shipment using the order-status page. | 0.32 |

D2 is the strongest result because its meaning includes both returning an item and receiving money back. D5 shares a product-resolution theme, but exchange is not the same as refund. This illustrates why ranking must be evaluated: a result can be semantically related without answering the query.

# 📊 8. Evaluating Retrieval Quality

A search system is useful only when relevant information appears near the top.

For a small learning exercise, we can evaluate results manually:

- Is the first result relevant?
- Does it directly answer the query or merely share a topic?
- Is an important result missing from the top-k?
- Are irrelevant results ranked too highly?
- Does paraphrasing the query change the ranking unexpectedly?
- Would keyword search perform better for this query?

For a larger labeled evaluation set, common measures include:

| Measure | Practical Question |
|---|---|
| Precision@k | How many of the top-k results are relevant? |
| Recall@k | How many of all known relevant results appear in the top-k? |
| Mean Reciprocal Rank | How early does the first relevant result appear? |

We do not need to calculate these metrics today. The important principle is that retrieval must be tested using representative queries and expected relevant documents.

## ⚠️ 8.1 Common Retrieval Failures

Semantic retrieval can fail because:

- The query is vague
- The knowledge base lacks the answer
- Chunks are too large or too small
- The embedding model does not understand the domain
- A semantically related document is factually wrong for the query
- Old documents remain searchable
- The chosen top-k is too small or too large
- Important exact terms are ignored

A high similarity score means “close according to this representation.” It does not mean “verified correct.”

## 🔗 8.2 Connection to RAG

Retrieval-Augmented Generation adds a language model after retrieval:

```text
user question
→ retrieve relevant chunks
→ provide chunks and question to an LLM
→ generate an answer grounded in the retrieved context
```

If retrieval misses the correct document, the language model may not receive the evidence it needs. Good generation cannot repair missing or misleading retrieval reliably.

This gives us an important RAG principle:

```text
retrieval quality limits answer quality
```

Day 6 focuses on finding the evidence. Day 7 will focus on how an LLM uses that evidence through grounding and RAG.

## 🔁 9. Chapter Summary

Semantic search turns the embedding concepts from Day 5 into a retrieval system:

```text
documents
→ chunks
→ stored embeddings

query
→ query embedding
→ similarity comparison
→ ranked top-k results
```

The main lessons are:

- Keyword search matches exact language
- Semantic search matches meaning
- Hybrid search can combine both signals
- Query and document vectors must be compatible
- Chunking determines what the system can retrieve precisely
- Top-k controls the balance between focus and coverage
- Similarity is a ranking signal, not proof of correctness
- Retrieval must be evaluated with realistic queries
- RAG depends on the quality of retrieved context

9. What does top-k mean?

### 10.2 Answer Key

1. Keyword search relies mainly on exact term overlap, while semantic search compares meaning through vector representations.
2. Keyword search may be better for exact error codes, product identifiers, names, or required legal phrases.
3. Vectors are meaningfully comparable only when they were created in the same compatible representation space.
4. Precomputing document embeddings avoids repeating expensive work for every query and allows faster search.
5. Chunking separates long, multi-topic documents into focused searchable units.
6. Large chunks may combine unrelated topics and produce vague or imprecise matches.
7. Small chunks may lose the context needed to understand or answer the query.
8. Cosine similarity provides a score used to rank document vectors against the query vector.
9. Top-k is the number of highest-ranked results returned by the retrieval system.
10. Increasing k may improve coverage but also introduce more irrelevant context.
11. Metadata filters enforce known constraints such as language, product, region, date, or document status before or during ranking.
12. Similarity measures closeness in the embedding space; it does not verify factual correctness, completeness, currency, or applicability.
13. Semantic search is not automatically superior. A keyword baseline reveals whether meaning-based retrieval provides a real improvement.
14. Precision@k asks what proportion of the top-k retrieved results are relevant.
15. RAG retrieves relevant context first and then provides that context to an LLM for grounded answer generation.
