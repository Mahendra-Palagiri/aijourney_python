# 🧠 4. From Text to Predicted Categories

Text classification assigns a predefined category to a piece of text. A spam filter assigns `spam` or `not spam`; a sentiment model assigns `positive` or `negative`; and a support-ticket system might assign `delivery`, `refund`, or `billing`.

Consider this customer message:

```text
"I was charged twice for my order."
```

A support-ticket classifier might return:

```text
billing
```

The classifier is not generating a new response. It is selecting from a known set of labels.

## 🏷️ 4.1 Labeled Examples

A supervised classifier learns from examples containing both the input text and its correct label.

| Text | Label |
|---|---|
| My package arrived late | delivery |
| Where is my shipment? | delivery |
| I want my money back | refund |
| Please return this item | refund |
| I was charged twice | billing |
| My payment failed | billing |

These examples allow the model to learn statistical relationships such as:

```text
package, shipment, tracking
→ delivery

refund, return, money back
→ refund

charged, payment, invoice
→ billing
```

In machine-learning notation:

```text
X = input examples or features
y = target labels
```

Initially, `X` contains raw text:

```text
X_text = [
    "My package arrived late",
    "I want a refund",
    "I was charged twice"
]
```

The corresponding targets are:

```text
y = [
    "delivery",
    "refund",
    "billing"
]
```

Most classical classifiers cannot use these sentences directly. TF-IDF must first convert them into numerical vectors. The classifier then learns how those vectors relate to the labels.

```text
TF-IDF creates numerical features.
The classifier learns how those features relate to categories.
```

# 🏗️ 5. Building a Reliable Classification Workflow

A classical text-classification workflow follows this sequence:

```text
collect labeled text
→ inspect the examples and labels
→ split raw text into training and testing sets
→ fit TF-IDF on the training text
→ train a classifier on the training features
→ predict labels for unseen test text
→ evaluate and inspect the predictions
```

Each stage has a specific responsibility:

| Stage | Purpose |
|---|---|
| Labeled dataset | Provides examples and correct outcomes |
| Train/test split | Reserves unseen text for evaluation |
| TF-IDF | Converts text into weighted numerical features |
| Classifier | Learns relationships between features and labels |
| Evaluation | Measures and explains prediction behavior |

## 🧪 5.1 Training and Testing

The training set teaches the vectorizer and classifier:

```text
training text + training labels
→ learned vocabulary, weights, and class patterns
```

The testing set asks:

```text
Can the completed pipeline classify text it did not learn from?
```

Evaluating with the training examples can produce an impressive score without demonstrating generalization.

```text
training accuracy = 100%
test accuracy = 55%
```

This result suggests that the model learned the training examples but does not handle unseen text reliably.

For classification, we often use a **stratified split** so the training and testing sets contain approximately the same class proportions:

```python
train_test_split(
    texts,
    labels,
    test_size=0.2,
    stratify=labels,
    random_state=42
)
```

`stratify=labels` preserves the label distribution as closely as possible. `random_state=42` makes the split reproducible.

## 🔢 5.2 TF-IDF and the Classifier

When fitted on the training text, TF-IDF learns the vocabulary, document frequencies, and term weights. It converts each document into a sparse vector:

```text
"My package has not arrived"
→ [0.00, 0.42, 0.00, 0.71, 0.31, ...]
```

A linear classifier then learns weights connecting those features to each category. Conceptually:

```text
delivery:
    tracking → positive weight
    shipment → positive weight
    delayed  → positive weight

refund:
    refund     → strong positive weight
    return     → positive weight
    money back → positive weight

billing:
    charged → strong positive weight
    payment → positive weight
    invoice → positive weight
```

For an unseen ticket, the classifier combines the evidence from its active features and chooses the strongest category. It is more than a single-keyword rule, but it still depends heavily on vocabulary patterns.

Common classifiers for sparse TF-IDF features include Logistic Regression, Multinomial Naive Bayes, and Linear Support Vector Machine. We use Logistic Regression because it is fast, effective with sparse features, relatively interpretable, and a strong baseline.

```text
TF-IDF + Logistic Regression
```

Starting with a baseline gives us evidence against which a more advanced method can later be compared.

## 🔗 5.3 Pipelines and Data Leakage

A scikit-learn pipeline connects the vectorizer and classifier:

```python
Pipeline([
    ("tfidf", TfidfVectorizer()),
    ("classifier", LogisticRegression())
])
```

It represents the complete path:

```text
raw text
→ TF-IDF transformation
→ class prediction
```

Keeping these stages together makes training and prediction consistent. It also reduces the risk of **data leakage**.

A leaky workflow would fit TF-IDF before separating the test data:

```text
fit TF-IDF on all text
→ split the data
→ train and evaluate
```

The vectorizer has already learned vocabulary and frequency information from the test text. The safer workflow is:

```text
split raw text first
→ fit the pipeline on training text only
→ use the fitted pipeline to predict test text
```

The test set must remain outside all training-related learning.

# 📊 6. Understanding Model Behavior

Accuracy, precision, recall, and F1-score are familiar concepts. Here, we use them to evaluate each text category rather than relearning their formulas.

| Metric | Reminder | NLP interpretation |
|---|---|---|
| Accuracy | Overall proportion predicted correctly | How often was the ticket category correct? |
| Precision | Correct predictions among predictions for a class | When we predicted `refund`, how often was it a refund? |
| Recall | Correct predictions among actual examples of a class | Of all refund tickets, how many did we find? |
| F1-score | Balance between precision and recall | Are both measures reasonably strong for this class? |

Overall accuracy can hide a weak class:

```text
overall accuracy = 90%
refund recall = 45%
```

The model appears strong overall but misses more than half of the real refund tickets. Possible causes include limited refund examples, overlapping refund and billing language, inconsistent labels, or unrepresentative training data.

## 🔍 6.1 Confusion Matrix and Individual Errors

A confusion matrix shows which actual categories were predicted correctly and which were confused.

| Actual \ Predicted | Delivery | Refund | Billing |
|---|---:|---:|---:|
| Delivery | 16 | 2 | 0 |
| Refund | 3 | 12 | 1 |
| Billing | 1 | 2 | 13 |

The diagonal represents correct predictions. The other cells reveal specific confusion patterns.

The matrix tells us **where** the model is confused. Reading the corresponding messages helps explain **why**.

Consider:

```text
"I returned the order but was charged again."
```

This message contains evidence for two categories:

```text
returned → refund
charged  → billing
```

The problem may not be limited to the model. We must also decide what the correct label should be when one message contains multiple issues. We might define a primary-label rule, allow multiple labels, route ambiguous cases to a person, or redesign overlapping categories.

Metrics summarize performance. Error analysis helps us improve the model, examples, labels, and task definition.

# 🔎 8. Program Walkthrough and Interpretation

In the separate Python program, `model.fit(X_train, y_train)` performs two learning steps:

1. TF-IDF learns its vocabulary and term weights from `X_train`.
2. Logistic Regression learns how those features relate to `y_train`.

The test text is not used during either step.

The setting:

```python
ngram_range=(1, 2)
```

allows TF-IDF to use individual words and two-word phrases:

```text
unigrams:
refund
charged
tracking

bigrams:
money back
wrong item
card declined
```

Bigrams preserve a small amount of local word order, but they do not provide deep language understanding.

When examining the output, we should ask:

- Did each class have reasonable precision, recall, and F1-score?
- Which classes were confused?
- Which messages were misclassified?
- Did those messages contain overlapping concepts?
- Were their expected labels clear?
- Does the dataset contain enough varied examples?

When the separate program is run, the example tickets have these expected meanings:

| New Ticket | Expected Class | Reason |
|---|---|---|
| The tracking page says my shipment is delayed | delivery | Refers to tracking, shipment, and delay |
| Please return my payment | refund | Requests that money be returned |
| My credit card was charged two times | billing | Describes a duplicate charge |

Because the training dataset is very small, the model may not always return all three expected classes. A different prediction is evidence to investigate, not a reason to alter the expected interpretation.

## ⚖️ 8.1 Strengths and Limitations

TF-IDF with Logistic Regression is fast, reproducible, relatively interpretable, and often effective for keyword-rich text. It is a useful baseline for future comparisons.

It may struggle with:

- Synonyms absent from training
- Complex word order
- Sarcasm
- Ambiguous messages
- Multiple issues in one message
- New domain-specific language

For example:

```text
"My parcel is still somewhere between the warehouse and my house."
```

If the training data contains only `package`, the model may not recognize that `parcel` expresses a similar idea. This limitation leads toward embeddings, which are the focus of Day 5.

## ⚠️ 8.2 Common Workflow Mistakes

- **Evaluating on training data:** measures memory rather than generalization.
- **Fitting TF-IDF before splitting:** leaks test information into training.
- **Looking only at accuracy:** can hide weak performance on an important class.
- **Using repetitive examples:** encourages narrow keyword learning.
- **Ignoring label quality:** gives the model conflicting instructions.
- **Trusting confidence as certainty:** a model can be confidently wrong.
