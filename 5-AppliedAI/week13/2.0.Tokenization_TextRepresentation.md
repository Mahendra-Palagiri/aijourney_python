## 🧠 Core Concept 1 — Why Tokenization Matters

In Day 1, we learned this basic NLP bridge:

```text
text → numbers → model/search/evaluation
```

Tokenization is one of the first steps in that bridge.

A model does not directly understand this sentence:

```text
"The food was excellent."
```

We first split it into smaller pieces:

```text
["The", "food", "was", "excellent"]
```

Those pieces are called **tokens**.

Simple definition:

```text
Tokenization = splitting text into useful pieces.
```

Most of the time, we can think of tokens as words.

But in modern NLP, tokens can also be word-pieces.

---

## 🧠 Core Concept 2 — Word-Level Tokenization

A simple tokenizer may split text by spaces.

Example:

```text
"The food was excellent"
```

becomes:

```text
["The", "food", "was", "excellent"]
```

Another example:

```text
"I loved the movie"
```

becomes:

```text
["I", "loved", "the", "movie"]
```

This seems easy.

But real text is messy.

Example:

```text
"I loved the movie!!!"
```

Should this become:

```text
["I", "loved", "the", "movie!!!"]
```

or:

```text
["I", "loved", "the", "movie", "!", "!", "!"]
```

or:

```text
["i", "loved", "the", "movie"]
```

There is no single perfect answer.

The tokenizer choice affects what the model sees.

---

## 🧠 Core Concept 3 — Lowercasing

Consider these two words:

```text
Food
food
```

To a human, they are usually the same word.

To a machine, they are different strings.

So we often lowercase text:

```text
"The Food Was Excellent"
```

becomes:

```text
"the food was excellent"
```

Then tokenization gives:

```text
["the", "food", "was", "excellent"]
```

Why this helps:

```text
Food, food, FOOD
```

all become:

```text
food
```

This reduces duplicate vocabulary entries.

But lowercasing can sometimes lose meaning.

Example:

```text
US
us
```

These are not always the same.

So preprocessing choices depend on the task.

---

## 🧠 Core Concept 4 — Punctuation

Punctuation can be noise or signal.

Example:

```text
"good"
"good!"
"good!!!"
```

For some tasks, punctuation may not matter much.

For sentiment analysis, punctuation may carry emotion.

```text
"That was great."
```

feels less intense than:

```text
"That was great!!!"
```

So we should not blindly remove punctuation without thinking.

The same rule keeps coming back:

```text
Preprocessing should match the task.
```

---

## 🧠 Core Concept 5 — Stop Words

**Stop words** are common words that often appear many times.

Examples:

```text
the
is
a
an
and
of
to
in
was
```

In some classical NLP workflows, we may remove stop words.

Example:

```text
"The food was excellent"
```

after stop word removal:

```text
["food", "excellent"]
```

This can help because common words may not add much meaning.

But again, it depends.

Example:

```text
"not good"
```

If we remove `not`, the meaning changes badly:

```text
"good"
```

That is a dangerous preprocessing mistake.

So stop word removal must be used carefully.

---

## 🧠 Core Concept 6 — Vocabulary

After tokenization, we build a vocabulary.

Suppose our corpus is:

```text
Document 1: "food was good"
Document 2: "food was excellent"
Document 3: "service was slow"
```

Tokens:

```text
Document 1: ["food", "was", "good"]
Document 2: ["food", "was", "excellent"]
Document 3: ["service", "was", "slow"]
```

Vocabulary:

```text
["excellent", "food", "good", "service", "slow", "was"]
```

The vocabulary is the set of unique tokens across all documents.

Each token can become a feature.

That is how we move from text to numbers.

---

## 🧠 Core Concept 7 — From Tokens to Feature Vectors

Let us use this vocabulary:

```text
["excellent", "food", "good", "service", "slow", "was"]
```

Now take this document:

```text
"food was good"
```

We count how many times each vocabulary word appears.

| Vocabulary Word | Count |
|---|---:|
| excellent | 0 |
| food | 1 |
| good | 1 |
| service | 0 |
| slow | 0 |
| was | 1 |

So the document becomes:

```text
[0, 1, 1, 0, 0, 1]
```

That vector is now numerical.

A model can use it.

This is the first idea behind **bag-of-words**.

---

## 🧠 Core Concept 8 — Why It Is Called Bag-of-Words

Bag-of-words means we count words but mostly ignore order.

Example:

```text
"food was good"
```

and:

```text
"good food was"
```

could produce the same vector.

Both contain:

```text
food = 1
was = 1
good = 1
```

So bag-of-words captures word presence or frequency.

But it loses word order.

That is a limitation.

Example:

```text
"dog bites man"
"man bites dog"
```

These have the same words but different meanings.

Bag-of-words may struggle with that.

---

## 🧠 Core Concept 9 — Text Length Problem

Different documents can have different lengths.

Example:

```text
Document 1: "good"
Document 2: "the food was really very good and the service was excellent"
```

ML models usually need fixed-length input.

Token lists are not fixed length:

```text
["good"]
```

versus:

```text
["the", "food", "was", "really", "very", "good", "and", "the", "service", "was", "excellent"]
```

A vocabulary-based vector solves this.

If the vocabulary has 10,000 words, every document becomes a vector of length 10,000.

Short document:

```text
[0, 0, 1, 0, 0, ...]
```

Long document:

```text
[3, 0, 1, 5, 0, ...]
```

Same vector length.

Different values.

---

## 🧠 Core Concept 10 — What We Gain and Lose

With basic tokenization and bag-of-words-style representation, we gain:

```text
text becomes numbers
documents become fixed-length vectors
simple ML models can use text
search and similarity become possible
```

But we lose:

```text
word order
deep meaning
context
sarcasm
some grammar
some sentence structure
```

This is why NLP evolves from:

```text
bag-of-words
```

to:

```text
TF-IDF
```

to:

```text
embeddings
```

to:

```text
transformers / LLMs
```

We learn them in order because the simple ideas explain the advanced ones.

## 📝 Concept Check

### Questions

1. What is tokenization?
2. Why might lowercasing help in NLP?
3. Why can lowercasing sometimes be risky?
4. What are stop words?
5. Why can removing stop words be dangerous for a phrase like “not good”?
6. What is vocabulary in NLP?
7. How does a document become a numerical vector?
8. What does bag-of-words lose when it ignores word order?

---

### Answer Key

1. Tokenization is the process of splitting text into smaller useful pieces called tokens. Tokens are often words, but they can also be word-pieces.

2. Lowercasing helps because it reduces duplicate vocabulary entries. For example, `Food`, `food`, and `FOOD` can all become `food`.

3. Lowercasing can be risky when capitalization carries meaning. For example, `US` may mean the United States, while `us` is a pronoun.

4. Stop words are very common words such as `the`, `is`, `a`, `and`, `of`, and `to`. They appear often and may not always add much task-specific meaning.

5. Removing stop words can be dangerous because some common words change the meaning. In `not good`, removing `not` changes the phrase into `good`, which reverses the meaning.

6. Vocabulary is the set of unique tokens found across the corpus.

7. A document becomes a numerical vector by comparing its tokens against the vocabulary and recording values such as word counts or word presence for each vocabulary term.

8. Bag-of-words loses word order. It may treat sentences with the same words but different meanings as similar, such as `dog bites man` and `man bites dog`.
