## 🧠 Core Concept

Training means the model updates its parameters to reduce loss.

For each training batch, the workflow is:

```text
forward pass → calculate loss → clear old gradients → backward pass → optimizer step
```

In PyTorch, that becomes:

```text
logits = model(images)
loss = loss_fn(logits, labels)
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

The key idea:

```text
backward() calculates gradients
optimizer.step() updates weights and biases
```

---

## 🧱 Training vs Validation

Training and validation are different.

### Training

Training is where the model learns.

During training:

```text
model.train()
forward pass
loss calculation
backward pass
optimizer step
weights update
```

The model parameters change during training.

---

### Validation

Validation is where we check model behavior on data it did not train on.

During validation:

```text
model.eval()
torch.no_grad()
forward pass
loss calculation
accuracy calculation
no weight update
```

The model parameters do not change during validation.

Validation helps us understand whether the model is learning general patterns or only memorizing training data.

---

## 🔢 Metrics We Track

For the baseline model, we track:

```text
training loss
training accuracy
validation loss
validation accuracy
```

### Training Loss

Training loss shows how wrong the model is on the training data.

If training loss decreases, the model is learning from the training batches.

---

### Validation Loss

Validation loss shows how wrong the model is on validation data.

If validation loss decreases, the model is learning patterns that generalize better.

---

### Training Accuracy

Training accuracy shows how often the model is correct on training data.

---

### Validation Accuracy

Validation accuracy shows how often the model is correct on validation data.

This is more important than training accuracy for judging general behavior.

---

## ⚠️ What We Watch For

### Healthy Learning Pattern

```text
training loss decreases
validation loss decreases or stabilizes
training accuracy increases
validation accuracy increases or stabilizes
```

This means the model is learning useful patterns.

---

### Underfitting Pattern

```text
training loss stays high
validation loss stays high
training accuracy stays low
validation accuracy stays low
```

This means the model may be too simple, not trained long enough, or not learning well.

---

### Overfitting Pattern

```text
training loss keeps decreasing
training accuracy keeps increasing
validation loss stops improving or gets worse
validation accuracy stops improving or gets worse
```

This means the model is fitting the training data more than the general pattern.

## Code Block 2 — Accuracy Helper Function

```python
def calculate_accuracy(logits, labels):
    predictions = torch.argmax(logits, dim=1)
    correct = (predictions == labels).sum().item()
    total = labels.size(0)
    return correct, total
```

What this does:

```text
logits → raw class scores
argmax → predicted class index
predictions == labels → correct predictions
correct / total → accuracy
```

This function returns counts instead of a percentage so we can accumulate accuracy across batches.

---

## Code Block 3 — Training Loop for One Epoch

```python
def train_one_epoch(model, train_loader, loss_fn, optimizer):
    model.train()

    total_loss = 0.0
    total_correct = 0
    total_examples = 0

    for images, labels in train_loader:
        logits = model(images)
        loss = loss_fn(logits, labels)

        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

        total_loss += loss.item() * images.size(0)

        correct, total = calculate_accuracy(logits, labels)
        total_correct += correct
        total_examples += total

    avg_loss = total_loss / total_examples
    avg_accuracy = total_correct / total_examples

    return avg_loss, avg_accuracy
```

Important details:

```text
model.train()              → puts model in training mode
optimizer.zero_grad()      → clears old gradients
loss.backward()            → calculates new gradients
optimizer.step()           → updates model parameters
loss.item() * batch_size   → accumulates total loss correctly
```

Why multiply loss by batch size?

`CrossEntropyLoss` gives the average loss for the batch. Multiplying by the batch size gives the total batch loss, so the final epoch average is accurate.

---

## Code Block 4 — Evaluation Loop

```python
def evaluate(model, data_loader, loss_fn):
    model.eval()

    total_loss = 0.0
    total_correct = 0
    total_examples = 0

    with torch.no_grad():
        for images, labels in data_loader:
            logits = model(images)
            loss = loss_fn(logits, labels)

            total_loss += loss.item() * images.size(0)

            correct, total = calculate_accuracy(logits, labels)
            total_correct += correct
            total_examples += total

    avg_loss = total_loss / total_examples
    avg_accuracy = total_correct / total_examples

    return avg_loss, avg_accuracy
```

Important details:

```text
model.eval()       → puts model in evaluation mode
torch.no_grad()    → stops gradient tracking
no backward()      → no gradients are calculated
no step()          → model parameters do not change
```

This loop can be used for validation and later for test evaluation.

## Code Block 5 — Train the Baseline Model

```python
baseline_history = []

for epoch in range(EPOCHS):
    train_loss, train_acc = train_one_epoch(
        baseline_model,
        train_loader,
        loss_fn,
        optimizer
    )

        baseline_model,
        val_loader,

```

What this gives us:

```text

```

## 🧠 Important Training Summary

The training loop updates the model.

The validation loop only checks the model.

The key difference is:

```text
training   → gradients + optimizer step + weight updates
validation → no gradients + no optimizer step + no weight updates
```

2. What does `model.train()` do?
3. What does `model.eval()` do?
4. Why do we use `torch.no_grad()` during validation?
5. What does `optimizer.zero_grad()` do?
6. What does `loss.backward()` calculate?
7. What does `optimizer.step()` update?
8. Why do we track validation accuracy instead of only training accuracy?
9. What would suggest that the baseline is underfitting?
10. What would suggest that the baseline is overfitting?

---

## ✅ Concept Check Answers

1. The purpose of training the baseline model is to create a simple reference result.

   Later, we can compare the improved model against this baseline and decide whether the improved model added value.

2. `model.train()` puts the model in training mode.

   This matters because some layers behave differently during training and evaluation. Even though our baseline does not use dropout or batch normalization, using `model.train()` is still the correct PyTorch habit.

3. `model.eval()` puts the model in evaluation mode.

   It tells PyTorch that we are checking the model, not training it.

4. We use `torch.no_grad()` during validation because we do not need gradients when evaluating.

   This saves memory, makes evaluation faster, and prevents accidental gradient tracking.

5. `optimizer.zero_grad()` clears old gradients from the previous batch.

   PyTorch accumulates gradients by default, so we must clear them before calculating new gradients.

6. `loss.backward()` calculates gradients for the model parameters.

   It tells us how each weight and bias contributed to the loss.

7. `optimizer.step()` updates the model parameters using the gradients.

   This is the step where weights and biases actually change.

8. We track validation accuracy because it shows how well the model performs on data it did not train on.

   Training accuracy alone can be misleading because a model can memorize the training data.

9. Underfitting may be happening if both training and validation loss stay high, and both training and validation accuracy stay low.

   This means the model is not learning the training data well enough.

10. Overfitting may be happening if training loss keeps decreasing and training accuracy keeps increasing, but validation loss gets worse or validation accuracy stops improving.

    This means the model is learning the training data better than the general pattern.
