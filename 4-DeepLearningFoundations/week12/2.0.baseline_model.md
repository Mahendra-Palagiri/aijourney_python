## 🧠 Core Concept

A baseline model gives us a simple first result.

For image data, the baseline model will flatten each image into a vector of numbers.

For FashionMNIST:

```text
one image shape: [1, 28, 28]
flattened size: 1 × 28 × 28 = 784
```

So one image becomes:

```text
[1, 28, 28] → [784]
```

For one batch:

```text
[64, 1, 28, 28] → [64, 784]
```

The baseline model then treats those 784 values like normal input features.

---

## 🧱 Baseline Model Flow

The baseline model flow is:

```text
image batch → flatten → Linear → ReLU → Linear → logits
```

More specifically:

```text
[64, 1, 28, 28]
→ flatten
[64, 784]
→ Linear(784 → hidden_size)
→ ReLU
→ Linear(hidden_size → 10)
→ logits
[64, 10]
```

The final output has shape:

```text
[batch_size, number_of_classes]
```

For FashionMNIST:

```text
[64, 10]
```

This means each image gets 10 class scores.

---

## 🔢 Why the Output Is Logits

The model does not directly output the final class name.

It outputs raw class scores called **logits**.

Example for one image:

```text
[1.8, -0.4, 0.2, 3.1, -1.0, 0.5, 2.2, -0.8, 0.7, 1.3]
```

There are 10 values because FashionMNIST has 10 classes.

The highest score becomes the predicted class.

We do not apply `softmax` inside the model because `CrossEntropyLoss` expects raw logits.

---

## 🧰 Model Choice

We will use a simple fully connected neural network:

```text
Flatten → Linear → ReLU → Linear
```

Reason:

- it is simple
- it uses Week 9 neural-network ideas
- it uses Week 10 PyTorch model-building workflow
- it gives us a fair starting point before the improved model

This baseline is not expected to be perfect. Its job is to give us a reference result.

---

## 🧪 Loss Function Choice

We will use:

```text
CrossEntropyLoss
```

Reason:

- this is a multi-class classification problem
- each image belongs to one of 10 classes
- the model outputs one logit score per class
- the labels are integer class indices, not one-hot vectors

Expected shapes:

```text
model output: [64, 10]
labels:       [64]
```

This is the correct shape pattern for `CrossEntropyLoss`.

---

## ⚙️ Optimizer Choice

We will use:

```text
Adam
```

Reason:

- it is a common optimizer for neural networks
- it adapts learning rates internally
- it is practical for a learning capstone
- it keeps the training setup simple

The optimizer updates the model parameters after gradients are calculated during training.

Training itself happens in the next phase.

# 💻 Practice Code

## Code Block 1 — Define Constants

```python
INPUT_SIZE = 1 * 28 * 28
HIDDEN_SIZE = 128
NUM_CLASSES = 10
LEARNING_RATE = 0.001
```

Meaning:

```text
INPUT_SIZE    → flattened image size
HIDDEN_SIZE   → number of neurons in the hidden layer
NUM_CLASSES   → number of output classes
LEARNING_RATE → optimizer step size
```

---

## Code Block 2 — Define the Baseline Model

```python
class BaselineNN(nn.Module):
    def __init__(self):
        super().__init__()

        self.flatten = nn.Flatten()
        self.network = nn.Sequential(
            nn.Linear(INPUT_SIZE, HIDDEN_SIZE),
            nn.ReLU(),
            nn.Linear(HIDDEN_SIZE, NUM_CLASSES)
        )

    def forward(self, x):
        x = self.flatten(x)
        logits = self.network(x)
        return logits
```

What happens inside the model:

```text
nn.Flatten()              → converts [64, 1, 28, 28] into [64, 784]
nn.Linear(784, 128)      → first fully connected layer
nn.ReLU()                → non-linear activation
nn.Linear(128, 10)       → output layer for 10 classes
```

---

## Code Block 3 — Create the Model

```python
baseline_model = BaselineNN()

print(baseline_model)
```

Expected model structure:

```text
BaselineNN(
  (flatten): Flatten(start_dim=1, end_dim=-1)
  (network): Sequential(
    (0): Linear(in_features=784, out_features=128, bias=True)
    (1): ReLU()
    (2): Linear(in_features=128, out_features=10, bias=True)
  )
)
```

## 📝 Concept Check

1. Why do we build a baseline model before the improved model?
2. What does `nn.Flatten()` do to `[64, 1, 28, 28]`?
3. Why is the baseline input size 784?
4. Why does the model output shape become `[64, 10]`?
5. What are logits?
6. Why should we not apply `softmax` inside the model before `CrossEntropyLoss`?
7. Why do labels have shape `[64]` instead of `[64, 10]`?
8. What does the optimizer receive from `baseline_model.parameters()`?
9. Why are we not calling `backward()` or `step()` yet in Phase 2?

---

## ✅ Concept Check Answers

1. We build a baseline first because it gives us a simple reference point.

   Later, when we build the improved model, we can compare it against the baseline instead of assuming the improved model is better.

2. `nn.Flatten()` converts the image batch from:

   ```text
   [64, 1, 28, 28]
   ```

   into:

   ```text
   [64, 784]
   ```

   It keeps the batch dimension and flattens the channel, height, and width dimensions.

3. The baseline input size is 784 because:

   ```text
   1 × 28 × 28 = 784
   ```

   Each image becomes 784 input features.

4. The model output shape becomes `[64, 10]` because:

   ```text
   64 → number of images in the batch
   10 → number of FashionMNIST classes
   ```

   Each image receives 10 class scores.

5. Logits are raw class scores produced by the model before converting them into probabilities or predicted labels.

6. We should not apply `softmax` inside the model because `CrossEntropyLoss` expects raw logits.

   `CrossEntropyLoss` internally handles the softmax-style calculation in a numerically stable way.

7. Labels have shape `[64]` because each image has one correct class index.

   The labels are integer class IDs, not one-hot encoded vectors.

8. The optimizer receives the model’s trainable parameters:

   ```text
   weights and biases
   ```

   These are the values the optimizer will update during training.

9. We are not calling `backward()` or `step()` yet because Phase 2 is only for model definition and forward-pass validation.

   Training begins in Phase 3.
