The improved model is different from the baseline architecture, but the training workflow is the same.

The same training loop can train either model as long as:

```text
the model accepts the input batch shape

the loss function matches the task
the optimizer receives that model's parameters
```


## ⚠️ Common Mistake

Do not reuse the baseline optimizer for the improved model.

Incorrect:

```python
# Wrong
train_one_epoch(improved_model, train_loader, loss_fn, baseline_optimizer)
```

Correct:

```python
# Correct
train_one_epoch(improved_model, train_loader, loss_fn, improved_optimizer)
```

Why?

Because the optimizer stores references to model parameters.

The baseline optimizer is connected to baseline model weights.

The improved optimizer must be connected to improved model weights.

# 💻 Practice Code

## Code Block 1 — Reuse Training and Evaluation Functions

We can reuse the same functions from Phase 3:

```python
def calculate_accuracy(logits, labels):
    predictions = torch.argmax(logits, dim=1)
    correct = (predictions == labels).sum().item()
    total = labels.size(0)
    return correct, total


def train_one_epoch(model, train_loader, loss_fn, optimizer):
    model.train()

    total_loss = 0.0
    total_correct = 0
    total_examples = 0

    for images, labels in train_loader:
        logits = model(images)
        loss = loss_fn(logits, labels)

        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

        batch_size = images.size(0)
        total_loss += loss.item() * batch_size

        correct, total = calculate_accuracy(logits, labels)
        total_correct += correct
        total_examples += total

    avg_loss = total_loss / total_examples
    avg_accuracy = total_correct / total_examples

    return avg_loss, avg_accuracy


def evaluate(model, data_loader, loss_fn):
    model.eval()

    total_loss = 0.0
    total_correct = 0
    total_examples = 0

    with torch.no_grad():
        for images, labels in data_loader:
            logits = model(images)
            loss = loss_fn(logits, labels)

            batch_size = images.size(0)
            total_loss += loss.item() * batch_size

            correct, total = calculate_accuracy(logits, labels)
            total_correct += correct
            total_examples += total

    avg_loss = total_loss / total_examples
    avg_accuracy = total_correct / total_examples

    return avg_loss, avg_accuracy
```

The functions do not care whether the model is fully connected or convolutional.

They only require:

```text
model(images) returns logits
loss_fn(logits, labels) works
optimizer updates that model's parameters
```

## Code Block 3 — Train the Improved Model

```python
improved_history = []

for epoch in range(EPOCHS):
    train_loss, train_acc = train_one_epoch(
        improved_model,
        train_loader,
        improved_loss_fn,
        improved_optimizer
    )

    val_loss, val_acc = evaluate(
        improved_model,
        val_loader,
        improved_loss_fn
    )

    epoch_result = {
        "epoch": epoch + 1,
        "train_loss": train_loss,
        "train_acc": train_acc,
        "val_loss": val_loss,
        "val_acc": val_acc
    }

    improved_history.append(epoch_result)

    print(
        f"Epoch {epoch + 1}/{EPOCHS} | "
        f"Train Loss: {train_loss:.4f} | "
        f"Train Acc: {train_acc:.4f} | "
        f"Val Loss: {val_loss:.4f} | "
        f"Val Acc: {val_acc:.4f}"
    )
```

This produces one row of improved-model metrics per epoch.

---

## ✅ Concept Check Answers

1. We can reuse the same training loop because both models accept image batches and return logits.

   The training loop only needs:

   ```text
   model(images) → logits
   loss_fn(logits, labels)
   optimizer updates model parameters
   ```

2. The model changes from the baseline model to the improved image-aware model.

   The optimizer also changes because it must be connected to the improved model's parameters.

3. We need a new optimizer because optimizers store references to a specific model's parameters.

   The improved model has different weights and biases from the baseline model.

4. If we used the baseline optimizer for the improved model, the improved model parameters would not be updated correctly.

   The optimizer would still be connected to the baseline model's parameters.

5. We keep the same train/validation split so the comparison remains fair.

   Both models should be judged on the same data split.

6. We keep the same loss function because the task has not changed.

   It is still multi-class classification with raw logits and integer labels.

7. We store results in `improved_history` so the improved model results stay separate from the baseline results.

   This makes Phase 6 comparison cleaner.

8. Before Phase 6, we need improved model training loss, training accuracy, validation loss, validation accuracy, and final validation result.

9. The improved model is learning if training loss decreases, training accuracy increases, and validation accuracy improves or stabilizes.

10. We do not declare the improved model better in Phase 5 because Phase 5 only creates the improved model's results.

    The actual comparison against the baseline happens in Phase 6.
