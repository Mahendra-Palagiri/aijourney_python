## 🧰 Key PyTorch Objects

### Dataset

A dataset stores examples.

Each example is usually:

```text
(image, label)
```

So one item from the dataset gives us:

```text
one image tensor
one label
```

---

### Transform

A transform changes raw data into the format PyTorch models expect.

For this phase, we mainly need:

```python
transforms.ToTensor()
```

This converts an image into a tensor.

For FashionMNIST, it changes the image into this shape:

```text
[1, 28, 28]
```

Meaning:

```text
1 channel
28 height
28 width
```

The `1` is because the image is grayscale.

---

### DataLoader

A `DataLoader` gives us batches.

Instead of giving the model one image at a time, it gives a group of images.

Example batch shape:

```text
[64, 1, 28, 28]
```

Meaning:

```text
64 images
1 channel each
28 height
28 width
```

---

## 🔢 Expected Tensor Shapes

For FashionMNIST:

### One Image

```text
[1, 28, 28]
```

Meaning:

```text
channels, height, width
```

---

### One Label

```text
single integer
```

Example:

```text
0
1
2
...
9
```

---

### One Batch of Images

If batch size is 64:

```text
[64, 1, 28, 28]
```

Meaning:

```text
batch size, channels, height, width
```

---

### One Batch of Labels

```text
[64]
```

Meaning:

```text
one label per image
```

---

## 🔗 Why This Matters for Week 12

The baseline model and improved model will use the same dataset, but they will treat the image differently.

### Baseline Model Later

The baseline will flatten the image:

```text
[64, 1, 28, 28] → [64, 784]
```

Why 784?

```text
1 × 28 × 28 = 784
```

So each image becomes 784 numbers.

---

### Improved Image-Aware Model Later

The improved model will keep image structure longer:

```text
[64, 1, 28, 28]
```

It will use the channel, height, and width structure directly.

So Phase 1 prepares the shared input pipeline for both models.

## Code Block 4 — Load Dataset

```python
train_full = datasets.FashionMNIST(
    root="data",
    train=True,
    download=True,
    transform=transform
)

test_data = datasets.FashionMNIST(
    root="data",
    train=False,
    download=True,
    transform=transform
)
```

What this does:

```text
train_full → original training dataset
test_data  → official test dataset
```

We will split `train_full` into:

```text
training set
validation set
```

The test set stays separate until final evaluation.

---

## Code Block 5 — Create Train/Validation Split

```python
train_size = int(0.8 * len(train_full))
val_size = len(train_full) - train_size

train_data, val_data = random_split(
    train_full,
    [train_size, val_size]
)
```

What this does:

```text
80% → training
20% → validation
```

Why validation exists:

```text
training set   → model learns from this
validation set → we check model behavior during development
test set       → final honest evaluation later
```

---

## Code Block 6 — Create DataLoaders

```python
train_loader = DataLoader(
    train_data,
    batch_size=BATCH_SIZE,
    shuffle=True
)

val_loader = DataLoader(
    val_data,
    batch_size=BATCH_SIZE,
    shuffle=False
)

test_loader = DataLoader(
    test_data,
    batch_size=BATCH_SIZE,
    shuffle=False
)
```

Why `shuffle=True` for training:

```text
The model should not see examples in the same fixed order every epoch.
```

Why `shuffle=False` for validation/test:

```text
We are only evaluating, not learning.
Order does not matter.
```

## 📝 Concept Check

1. What is the shape of one FashionMNIST image after `ToTensor()`?
2. What does `[64, 1, 28, 28]` mean?
3. Why do labels have shape `[64]` instead of `[64, 10]`?
4. Why do we use `shuffle=True` for the training loader?
5. Why do we keep a validation set separate from the test set?
6. Why will the baseline later flatten the image into 784 numbers?
7. Why should both models use the same train/validation/test split?

## ✅ Concept Check Answers

1. One FashionMNIST image has shape:

   ```text
   [1, 28, 28]
   ```

   This means 1 grayscale channel, 28 pixels height, and 28 pixels width.

2. `[64, 1, 28, 28]` means:

   ```text
   64 images in the batch
   1 grayscale channel per image
   28 pixels height
   28 pixels width
   ```

3. Labels have shape `[64]` because each image has one correct class label.

   Each label is a single integer from 0 to 9, not a full one-hot vector.

4. We use `shuffle=True` for the training loader so the model does not see training examples in the same fixed order every epoch.

   This helps make training less dependent on the original order of the data.

5. We keep a validation set separate from the test set because they serve different purposes:

   ```text
   validation set → used during development to compare model behavior
   test set       → used at the end for final evaluation
   ```

   The test set should stay untouched until the final selected model is evaluated.

6. The baseline later flattens the image into 784 numbers because:

   ```text
   1 × 28 × 28 = 784
   ```

   A fully connected baseline expects each image as a flat feature vector.

7. Both models should use the same train/validation/test split so the comparison is fair.

   If the baseline and improved model use different data splits, we cannot tell whether the performance difference came from the model or from the data.
