## 🧠 Core Concept

The baseline model flattened the image immediately:

```text
[64, 1, 28, 28] → [64, 784]
```

That was required because the baseline used fully connected `Linear` layers.

The improved model does not flatten immediately.

It keeps the image in this shape first:

```text
[batch_size, channels, height, width]
```

For FashionMNIST:

```text
[64, 1, 28, 28]
```

This allows convolution layers to learn local image patterns before the final classifier.

---

## 🧱 Improved Model Flow

The improved model flow is:

```text
image batch
→ Conv2d
→ ReLU
→ MaxPool2d
→ Conv2d
→ ReLU
→ MaxPool2d
→ Flatten
→ Linear
→ logits
```

A more concrete version:

```text
[64, 1, 28, 28]
→ Conv2d(1 → 16)
→ ReLU
→ MaxPool2d
→ Conv2d(16 → 32)
→ ReLU
→ MaxPool2d
→ Flatten
→ Linear
→ [64, 10]
```

The final output still needs to be:

```text
[batch_size, number_of_classes]
```

For FashionMNIST:

```text
[64, 10]
```

---

## 🔍 Why We Do Not Flatten First

For the baseline model, we flattened first because `nn.Linear` expects this shape:

```text
[batch_size, input_features]
```

But the improved image-aware model starts with `Conv2d`.

`Conv2d` expects this shape:

```text
[batch_size, channels, height, width]
```

So for the improved model, we keep:

```text
[64, 1, 28, 28]
```

and only flatten later, after convolution and pooling have extracted spatial features.

Core difference:

```text
Baseline:
image → flatten → Linear → ReLU → Linear

Improved model:
image → Conv2d → ReLU → Pool → Conv2d → ReLU → Pool → flatten → Linear
```

---

## 🧩 What `Conv2d` Does

A convolution layer scans small filters across the image.

A filter looks at a small local region at a time.

For example, a `3 × 3` filter looks at a small patch of 9 pixels.

The filter can learn simple local patterns such as:

```text
edges
curves
corners
textures
small shapes
```

The output of a convolution layer is called a **feature map**.

A feature map shows where a learned pattern appears in the image.

---

## 🔢 Shape Flow for This Model

We will use this structure:

```text
Conv2d(1, 16, kernel_size=3, padding=1)
ReLU
MaxPool2d(kernel_size=2)
Conv2d(16, 32, kernel_size=3, padding=1)
ReLU
MaxPool2d(kernel_size=2)
Flatten
Linear(32 * 7 * 7, 10)
```

### Input

```text
[64, 1, 28, 28]
```

---

### After First Convolution

```text
Conv2d(1 → 16, kernel_size=3, padding=1)
```

Output shape:

```text
[64, 16, 28, 28]
```

Why height and width stay 28:

```text
padding=1 keeps spatial size the same for a 3×3 kernel
```

---

### After First Pooling

```text
MaxPool2d(kernel_size=2)
```

Output shape:

```text
[64, 16, 14, 14]
```

Pooling halves the height and width:

```text
28 → 14
```

---

### After Second Convolution

```text
Conv2d(16 → 32, kernel_size=3, padding=1)
```

Output shape:

```text
[64, 32, 14, 14]
```

The number of channels changes from 16 to 32.

Height and width stay 14 because of padding.

---

### After Second Pooling

```text
MaxPool2d(kernel_size=2)
```

Output shape:

```text
[64, 32, 7, 7]
```

Pooling halves the height and width again:

```text
14 → 7
```

---

### After Flattening

```text
[64, 32, 7, 7] → [64, 1568]
```

Why 1568?

```text
32 × 7 × 7 = 1568
```

---

### Final Output

```text
Linear(1568 → 10)
```

Output shape:

```text
[64, 10]
```

This gives 10 class scores per image.

## Code Block 2 — Define the Improved Model

```python
class ImprovedImageModel(nn.Module):
    def __init__(self):
        super().__init__()

        self.features = nn.Sequential(
            nn.Conv2d(in_channels=1, out_channels=16, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(kernel_size=2),

            nn.Conv2d(in_channels=16, out_channels=32, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(kernel_size=2)
        )

        self.flatten = nn.Flatten()

        self.classifier = nn.Linear(
            in_features=32 * 7 * 7,
            out_features=NUM_CLASSES
        )

    def forward(self, x):
        x = self.features(x)
        x = self.flatten(x)
        logits = self.classifier(x)
        return logits
```

What this model does:

```text
self.features   → learns image-aware spatial features
self.flatten    → converts feature maps into a vector
self.classifier → produces class logits
```

3. What does a convolution filter learn?
4. Why do we use ReLU after convolution?
5. What does `MaxPool2d(kernel_size=2)` do to height and width?
6. Why does the shape become `[64, 32, 7, 7]` before flattening?
7. Why is the flattened size `32 * 7 * 7 = 1568`?
8. Why does the final output shape need to be `[64, 10]`?
9. Why do we still use `CrossEntropyLoss` for the improved model?
10. Why are we not training the improved model in Phase 4?

---

## ✅ Concept Check Answers

1. We do not flatten before the first `Conv2d` layer because convolution needs the image-shaped tensor.

   `Conv2d` expects:

   ```text
   [batch_size, channels, height, width]
   ```

   If we flatten first, we destroy the spatial structure that convolution is designed to use.

2. `Conv2d` expects input shaped like:

   ```text
   [batch_size, channels, height, width]
   ```

   For FashionMNIST with batch size 64:

   ```text
   [64, 1, 28, 28]
   ```

3. A convolution filter learns local patterns from small image regions.

   Examples include edges, curves, corners, textures, or small shapes.

4. We use ReLU after convolution to add non-linearity.

   Without non-linearity, stacking layers would behave too much like one large linear transformation.

5. `MaxPool2d(kernel_size=2)` reduces height and width by half.

   Example:

   ```text
   28 × 28 → 14 × 14
   14 × 14 → 7 × 7
   ```

6. The shape becomes `[64, 32, 7, 7]` because:

   ```text
   batch size stays 64
   second convolution outputs 32 channels
   first pooling changes 28 → 14
   second pooling changes 14 → 7
   ```

7. The flattened size is 1568 because:

   ```text
   32 × 7 × 7 = 1568
   ```

   There are 32 feature maps, each of size 7 by 7.

8. The final output shape needs to be `[64, 10]` because there are 64 images in the batch and 10 FashionMNIST classes.

   Each image needs one score for each class.

9. We still use `CrossEntropyLoss` because the task is still multi-class classification.

   The improved model still outputs raw logits, and the labels are still integer class indices.

10. We are not training the improved model in Phase 4 because this phase is only for model definition and forward-pass validation.

    Training begins in Phase 5.
