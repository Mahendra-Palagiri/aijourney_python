# Week 14 — Applied AI: Computer Vision

## 🧭 Week Purpose

Week 14 continues the Applied AI phase by moving from language data to real-world image data.

We already learned CNN mechanics in Week 11 and defended an image-classification workflow in the Week 12 capstone. This week does not repeat those foundations. It upgrades them into a practical computer-vision toolkit:

```text
real images
→ reliable input pipeline
→ augmentation and normalization
→ modern training toolkit
→ transfer learning
→ evaluation and error analysis
→ applied CV decision
```

The central question is:

```text
How do we turn a working CNN experiment into a reliable applied computer-vision workflow?
```

# Day 1 — Real Image Data, Normalization, and Augmentation

## 📚 Topics

- torchvision datasets and transforms
- PIL images and `[C, H, W]` tensors
- Resize, crop, flip, color jitter, and normalization
- Train transforms versus evaluation transforms
- Augmentation as regularization
- Label-safe augmentation

## 🎯 Learning Goals

- Build the path from image file to transformed tensor and DataLoader
- Explain normalization using per-channel mean and standard deviation
- Explain why augmentation is applied only to training data
- Judge whether a transform preserves labels for the current task

## 🧠 Core Idea

Augmentation creates varied, label-preserving versions of training images. It can reduce overfitting, but only when the transformation preserves the meaning of the label.

```text
horizontal flip for cats → usually safe
horizontal flip for text → often unsafe
color jitter for objects → often useful
color jitter for color-dependent diagnosis → potentially harmful
```

## ✅ Day 1 Output

- Training and evaluation transform pipelines
- Dataset statistics or a justified normalization choice
- Augmentation gallery
- Written label-safety decisions

## 📚 Topics

- Dropout

## 🎯 Learning Goals

- Explain when dropout is active and why `model.eval()` matters
- Explain BatchNorm train-time statistics and evaluation-time running statistics
- Apply weight decay and a learning-rate schedule deliberately
- Use validation performance for early stopping without touching the test set

## 🧠 Core Idea

These tools solve different problems. They should be tested through controlled comparisons rather than stacked blindly.

```text
dropout → discourages reliance on individual activations
BatchNorm → stabilizes feature distributions during training
weight decay → discourages overly large weights
scheduler → changes learning rate over time
early stopping → selects a validation-supported stopping point
```

# Day 3 — Transfer Learning

## 📚 Topics

- Pretrained CNN features
- ResNet architecture at a practical level
- Feature extraction
- Frozen backbones
- Partial and full fine-tuning
- Differential learning rates

## 🎯 Learning Goals

- Explain how visual features progress from edges to textures, parts, and objects
- Replace a pretrained model's classification head
- Compare frozen-feature and fine-tuning strategies
- Select a strategy based on dataset size and domain similarity

## 🧠 Core Idea

Transfer learning reuses representations learned from a large source dataset.

```text
small data + similar domain → freeze most of the backbone
more data or larger domain shift → fine-tune more layers
new head → usually needs a larger learning rate
pretrained backbone → usually needs a smaller learning rate
```

## ✅ Day 3 Output

- From-scratch baseline

## 📝 Concept Check

1. Why should training and evaluation transforms differ?
2. Why can an augmentation be safe for one task and harmful for another?
3. What does image normalization do?
4. Why does `model.eval()` matter for dropout and BatchNorm?
5. What is the purpose of early stopping?
6. What is transfer learning?
7. When might a frozen backbone be preferable to full fine-tuning?
8. Why might the new classification head use a larger learning rate than the backbone?
9. Why is overall accuracy insufficient for CV evaluation?
10. What can a confusion matrix reveal?
11. Why should Grad-CAM be treated as evidence rather than proof?
12. What does gradient accumulation change?
13. What must a training checkpoint contain for a clean resume?
14. How do classification, detection, and segmentation outputs differ?
15. What evidence should support the Week 14 final model choice?

## ✅ Concept Check Answers

1. Training transforms may include random augmentation to improve generalization, while evaluation transforms must be deterministic so results are stable and comparable.
2. Label safety depends on the meaning of the target. A flip may preserve an animal class but change a digit, letter, orientation, or medical interpretation.
3. Normalization centers and scales image channels using means and standard deviations so inputs have a controlled numerical scale.
4. Dropout must turn off during evaluation, while BatchNorm must use learned running statistics instead of current-batch statistics.
5. Early stopping selects a validation-supported training point and helps avoid continuing after generalization stops improving.
6. Transfer learning reuses representations learned by a model on a large source dataset for a new related task.
7. A frozen backbone can be preferable when the new dataset is small or similar to the pretraining domain because it reduces overfitting and training cost.
8. The new head begins untrained and needs larger updates, while aggressive updates can damage useful pretrained backbone features.
9. Overall accuracy can hide weak classes, imbalance, systematic errors, and fragile behavior under real-world image variation.
10. A confusion matrix reveals which true classes are being mistaken for which predicted classes.
11. Grad-CAM provides a coarse visualization of influential regions but does not prove the full causal reasoning of the model.
12. Gradient accumulation combines gradients from multiple micro-batches before an optimizer step, creating a larger effective batch without storing the full batch at once.
13. A useful checkpoint includes model state, optimizer state, epoch or step, best metric, and other state needed to continue consistently.
14. Classification returns image-level labels, detection returns labels and boxes, and segmentation returns per-pixel labels.
15. The decision should use fair validation and holdout results, per-class behavior, error types, robustness, training cost, data limitations, and intended use.
