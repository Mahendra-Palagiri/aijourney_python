# Day 2 — Text Cleaning, Tokenization, and Vocabulary

## 📚 Topics

- Lowercasing
- Removing extra spaces
- Removing punctuation when appropriate
- Tokenization
- Vocabulary
- Sequence length
- Padding intuition

## 🎯 Learning Goals

By the end of Day 2, we should be able to:

- clean simple text
- split text into tokens
- create a vocabulary
- explain why sequence length matters
- explain padding at a practical level

## 🧠 Core Concept

Tokenization means splitting text into smaller pieces.

Example:

```text
"I like machine learning"
```

Tokens:

```text
["I", "like", "machine", "learning"]
```

A vocabulary is the set of known tokens.

Example vocabulary:

```text
["i", "like", "machine", "learning"]
```

A model does not see words the same way we do.

It sees tokens or token IDs.

## 🔢 Token IDs

Example:

```text
Vocabulary:
{"i": 0, "like": 1, "machine": 2, "learning": 3}
```

Text:

```text
"i like learning"
```

Token IDs:

```text
[0, 1, 3]
```

## 🧩 Sequence Length and Padding

Different sentences have different lengths.

Example:

```text
"good product" → 2 tokens
"delivery was late but product is good" → 7 tokens
```

Many models need fixed-length inputs.

Padding adds placeholder values to make sequences the same length.

Example:

```text
[4, 9] → [4, 9, 0, 0, 0]
```

# Day 3 — Bag-of-Words and TF-IDF

## 📚 Topics

- Bag-of-words

## 🎯 Learning Goals

By the end of Day 3, we should be able to:

- explain bag-of-words
- create a simple count-vector representation
- explain what TF-IDF improves
- identify why bag-of-words and TF-IDF ignore deep meaning

## 🧠 Core Concept — Bag-of-Words

Bag-of-words represents text by counting words.

Example vocabulary:

```text
["good", "bad", "product"]
```

Text:

```text
"good product good"
```

Bag-of-words vector:

```text
[2, 0, 1]
```

Meaning:

```text
"good" appears 2 times
"bad" appears 0 times
"product" appears 1 time
```

Bag-of-words is simple and useful, but it ignores word order.

## 🧠 Core Concept — TF-IDF

TF-IDF gives higher weight to words that are important in a document but not common everywhere.

Simple intuition:

```text
common words → lower weight
distinctive words → higher weight
```

Example:

```text
"the", "is", "and" → usually less useful
"refund", "battery", "delivery" → often more useful
```

## ⚖️ Bag-of-Words vs TF-IDF

| Method | What It Uses | Strength | Limitation |
|---|---|---|---|
| Bag-of-words | Word counts | Simple and easy to explain | Treats common words as important unless filtered |
| TF-IDF | Weighted word importance | Better for search/classification | Still does not deeply understand meaning |

# Day 5 — Embeddings and Cosine Similarity

## 📚 Topics

- Dense vectors
- Word embeddings
- Sentence embeddings
- Similar meaning in vector space
- Cosine similarity
- Similarity scores

## 🎯 Learning Goals

By the end of Day 5, we should be able to:

- explain embeddings at a practical level
- explain why embeddings are different from bag-of-words
- calculate or interpret cosine similarity
- use embeddings to compare text meaning

## 🧠 Core Concept — Embeddings

Embeddings convert text into dense numeric vectors.

Unlike bag-of-words, embeddings try to capture meaning.

Example:

```text
"car"
"automobile"
```

These words are different strings but similar in meaning.

An embedding model should place them close together in vector space.

## 📐 Core Concept — Cosine Similarity

Cosine similarity compares vector direction.

It answers:

```text
Are these two vectors pointing in a similar direction?
```

For text embeddings, this roughly means:

```text
Are these two pieces of text similar in meaning?
```

Similarity examples:

```text
high similarity → texts are meaningfully related
low similarity → texts are less related
negative similarity → vectors point in opposite directions
```

# Day 6 — Semantic Search and Retrieval

## 📚 Topics

- Keyword search
- Semantic search
- Query embedding
- Document embedding
- Similarity ranking
- Retrieval
- Top-k results

## 🎯 Learning Goals

By the end of Day 6, we should be able to:

- explain keyword search vs semantic search
- represent a query and documents as vectors
- compare query-to-document similarity
- retrieve top matching documents
- explain how retrieval connects to RAG

## 🧠 Core Concept

Keyword search looks for matching words.

Semantic search looks for similar meaning.

Example query:

```text
How do I return an item?
```

Relevant document:

```text
Refunds are available within 30 days of purchase.
```

Keyword search may miss this because the exact words are different.

Semantic search may find it because the meaning is related.

## 🔎 Retrieval Flow

```text
user query
→ convert query to embedding
→ convert documents to embeddings
→ calculate similarity
→ rank documents
→ return top matches
```

## 🧠 Core Concept — Grounding

Grounding means giving the model relevant context before it answers.

Instead of asking a model to answer from memory only, we provide source information.

Simple grounding flow:

```text
question
→ relevant context
→ answer based on that context
```

## 🧠 Core Concept — RAG

RAG stands for Retrieval-Augmented Generation.

Simple RAG flow:

```text
user question
→ retrieve relevant documents
→ pass retrieved text to language model
→ generate grounded answer
```

RAG combines:

```text
retrieval + generation
```

Retrieval finds useful context.

Generation turns that context into an answer.

## ⚠️ Responsible NLP Risks

NLP systems can fail in subtle ways.

Risks include:

```text
hallucination
bias
privacy leakage
wrong retrieval results
misleading summaries
overconfidence
missing context
```

A useful NLP workflow must be evaluated, not just demonstrated.

## ✅ Concept Check Answers

1. Raw text cannot usually be fed directly into an ML model because most models need numeric input. Text must first be converted into numbers using methods such as bag-of-words, TF-IDF, token IDs, or embeddings.

2. Tokenization means splitting text into smaller pieces such as words, subwords, or characters.

3. A vocabulary is the set of known tokens or words that a text system uses to represent documents numerically.

4. Bag-of-words counts how many times each word from the vocabulary appears in a piece of text.

5. TF-IDF tries to reduce the importance of very common words and increase the importance of words that are more distinctive to a document.

6. An embedding is a dense numeric vector that represents a word, sentence, or document in a way that tries to capture meaning.

7. Cosine similarity is useful because it compares the direction of two vectors. For text embeddings, similar direction often means similar meaning.

8. Keyword search looks for matching words. Semantic search looks for similar meaning, even when the exact words are different.

9. Grounding means giving a model relevant context or source information so its answer is based on that context instead of only its internal knowledge.

10. RAG stands for Retrieval-Augmented Generation. It retrieves relevant information first, then uses that information to help generate a grounded answer.

11. We evaluate NLP workflows because language outputs can look convincing even when they are wrong, biased, incomplete, or unsupported. Evaluation helps us check correctness, relevance, and reliability.

12. Week 12 taught us not to assume that a more advanced method is better. Week 13 uses the same mindset: compare classical NLP, embeddings, and LLM-style workflows using evidence instead of assumptions.
