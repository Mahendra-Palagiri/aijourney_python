# Week C — Day 3: Density & Hierarchy — DBSCAN and Agglomerative Clustering
> Pairs with `3.1.dbscan-hierarchical.py`

## 📚 Topics
DBSCAN (core/border/noise points, eps & min_samples), why density methods find arbitrary shapes,
agglomerative clustering, linkage criteria, reading dendrograms.

## 🎯 Learning Goals
1. Define core point (≥ min_samples within eps), border, noise; narrate DBSCAN's flood-fill expansion.
2. Explain why DBSCAN needs NO k, finds non-spherical clusters, and labels outliers natively (-1) — the three
   things k-means can't do — and its cost: eps is hard to set, struggles with varying densities.
3. Use the k-distance plot to choose eps (the "knee" heuristic).
4. Narrate agglomerative clustering: start n clusters, repeatedly merge the closest pair; linkage = the
   definition of "closest" (single/complete/average/Ward) and how each shapes results (chaining vs compact).
5. Read a dendrogram: heights = merge distances; cutting it = choosing k AFTER seeing structure.

## 🔍 Core Mechanics
- DBSCAN's eps & min_samples jointly define density; min_samples ≈ 2·dims is a sane start; vary eps on a slider mentally.
- Ward linkage minimizes within-cluster variance growth — agglomerative's cousin of k-means' objective.
- Both methods still live on DISTANCES → scaling still mandatory.

## 🛠️ Build in the paired .py
1. The three-way shootout: k-means vs DBSCAN vs Ward on blobs / moons / varied-density blobs (one figure, 9 panels) —
   the single most instructive plot in clustering.
2. k-distance plot for moons; pick eps at the knee; show result sensitivity to eps ±20%.
3. Dendrogram on a 30-sample subset (scipy linkage + dendrogram); cut at 2 heights; map to cluster labels.
4. Use DBSCAN's noise label as an outlier detector on Titanic numeric features; eyeball the flagged rows.

## ⚠️ Common Mistakes
One global eps on varying densities · forgetting min_samples interacts with dimensionality ·
dendrogram heights read as "importance" rather than merge distance.
