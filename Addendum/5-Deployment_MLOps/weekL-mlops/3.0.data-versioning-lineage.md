# Week L — Day 3: Data Versioning & Lineage — The Third Axis of Reproducibility
> Pairs with `3.1.data-versioning-lineage.py` · `pip install dvc`

## 📚 Topics
Why git can't hold data (size, churn) yet experiments are meaningless without data identity; content-hash
thinking; DVC basics (track, push to a local/remote cache, checkout old versions); dataset documentation
(the data/ folder's missing READMEs, finally); train/serve data contracts.

## 🎯 Learning Goals
1. Complete the reproducibility triangle: code (git, Week J-5) + environment (Docker, Week K-3) + DATA
   (today) — an experiment is the join of all three; your tracker should record all three identities.
2. Get content-addressing: a dataset version IS its hash; DVC stores hashes in git-tracked .dvc files while
   bytes live in a cache — git history now implies data history.
3. Version the addendum's datasets with DVC: track, modify (inject the Week-K drift simulation data!),
   commit, then CHECKOUT the old version and reproduce an old result exactly — time travel, demonstrated.
4. Write the data documentation debt off: a README per data source (provenance, schema, units, known quirks,
   license — the main repo's data/ folder never had one; the addendum sets the standard).
5. Define a data CONTRACT for the serving path: expected schema + ranges as code (pandera or pydantic),
   enforced in training AND serving (one contract, two enforcement points — Week K's skew protection, completed).

## 🛠️ Build in the paired .py

logged nowhere (back to square one) · contracts written once, enforced never (wire them or delete them).
