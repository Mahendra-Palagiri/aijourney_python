# Week L — Day 4: Pipelines & Orchestration — Retraining While You Sleep
> Pairs with `4.1.pipelines-orchestration.py`

## 📚 Topics
From notebook-order-of-execution to explicit DAGs; what orchestrators do (dependencies, retries, schedules,
backfills); the honest small-scale version (a Makefile/Python DAG + cron) before the heavy tools (Airflow/
Prefect/Dagster surveyed, one tasted); the retraining pipeline assembled from Weeks J–L parts.

## 🎯 Learning Goals
1. See your workflow as a DAG: ingest → validate (L-3 contract) → features (J-4 SQL) → train (tracked, L-1)
   → evaluate (harness) → register (L-2) → promote-if-worthy (L-2 criteria) → drift-report (K-5). You own
   every node ALREADY; orchestration is just edges + automation.
2. Build it minimally first: each node a CLI module (Week J-2 foresight pays off), a ~50-line Python runner
   with dependency order, per-node logging, idempotency (K-4's lesson), and failure stops-the-line.
3. Schedule it: cron entry (or the platform's scheduler) for nightly retraining on the simulated-drift data —
   wake up to a new candidate model and its evaluation report (not auto-promoted! the L-2 gate stands).
4. Taste one real orchestrator (Prefect is the gentlest): the same DAG, now with retries, UI, and observed
   runs — judge what the framework buys over your runner (and what it costs in complexity).
5. Know the failure modes to design for: partial failure mid-DAG (idempotent nodes resume), upstream data
   late (validation gate catches), silent node success with garbage output (contracts between nodes — L-3 again).

## 🛠️ Build in the paired .py
1. The minimal runner + the 8-node retraining DAG, run end-to-end manually.
2. The scheduled run (cron/scheduler) + the morning-after artifacts committed (run log, new candidate, eval report, promotion decision).
3. The same DAG in Prefect; a ½-page comparison verdict (when is the framework worth it: team size? node count? retry needs?).
4. The partial-failure drill: kill node 4 mid-run; resume; verify no duplicates/corruption (idempotency, proven again).

## ⚠️ Common Mistakes
Auto-promotion (the gate exists because 3am-trained models meet 9am-quality criteria) · DAG nodes sharing
state through global files with no contracts · adopting Airflow for a 3-node personal project (the minimal
runner WAS the lesson).
