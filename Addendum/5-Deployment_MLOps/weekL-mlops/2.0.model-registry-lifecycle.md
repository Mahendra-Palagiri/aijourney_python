# Week L — Day 2: Model Registry & Lifecycle — From "best run" to "the model in prod"
> Pairs with `2.1.model-registry-lifecycle.py`

## 📚 Topics
The gap between an experiment and a deployed artifact, MLflow Model Registry (registered models, versions,
stages/aliases), promotion criteria as CODE, loading by alias from the serving layer, rollback as a
one-line operation.

## 🎯 Learning Goals
1. Name the lifecycle: trained → registered → validated → promoted (staging→production alias) → serving loads
   by alias → deprecated/rolled back. Each arrow is a DECISION with criteria — write them down.
2. Register the Week-K serving model properly: version 1, with lineage to its tracking run (params, data,
   evaluation report all one click away — the orphan-model problem from Week K-1, solved at the root).
3. Encode promotion as a script, not a vibe: `promote.py` checks the candidate's logged metrics against
   thresholds AND beats-current-production-by-X AND harness report present → then flips the alias. (Your
   Week-7/8 decision-rule discipline, made executable.)
4. Wire serving to the registry: Week-K's API loads "models:/churn@production" at startup — deploy a new
   version by promotion, no code change; roll back by alias flip; DRILL both.
5. Know the alternative implementations (a registry is a pattern: W&B, SageMaker, or even a disciplined
   s3+manifest) — the concepts transfer; the tool is incidental.

## 🛠️ Build in the paired .py
1. Register v1 + v2 (a retrained variant) of the Week-K model with full lineage.
2. `promote.py` with criteria; run it: v2 passes/fails on its merits (engineer one of each case).
3. The API loading by alias; the promotion → new-version-served-without-redeploy demo, logged.
4. The rollback drill: flip back, verify serving, time it (the number goes in the runbook).

## ⚠️ Common Mistakes
Promotion criteria living in someone's head · serving pinned to a version number (alias indirection is the
point) · registry adopted but artifacts still ALSO passed around by file path (one door).
