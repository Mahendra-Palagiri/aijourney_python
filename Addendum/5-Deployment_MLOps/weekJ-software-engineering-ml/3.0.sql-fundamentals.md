## 📚 Topics
Relational model (tables/keys/relationships), SQLite (zero-install, perfect for learning), SELECT-WHERE-

three-valued logic traps.

## 🎯 Learning Goals
1. Map SQL ↔ pandas in both directions for every verb you know: WHERE↔boolean mask, GROUP BY↔groupby,
   JOIN↔merge, HAVING↔post-agg filter — you already think in these; today you learn their native tongue.
2. Write JOINs with confidence: INNER vs LEFT (and when rows multiply! — the merge `validate=` lesson from
   your pandas cheat sheet, at its source), keys, the unmatched-rows question asked EVERY time.
3. Use GROUP BY + HAVING for the questions Week 2/4 answered in pandas (survival rate by class×sex on a
   Titanic SQLite db — same answers, new tool, checked against pandas).
4. Compose CTEs (`WITH`) for readable multi-step queries — the pipeline thinking you already have, in SQL.
5. Respect NULL: `= NULL` never matches, `IS NULL`, COUNT(col) vs COUNT(*), NULLs in aggregates — the
   missing-data lessons of Week 4, three-valued edition.

## 🛠️ Build in the paired .py
1. Build `titanic.db` (sqlite3 + pandas .to_sql, split into passengers/tickets/survival tables — a real schema with keys).
2. 15-query drill ladder (filtering → aggregation → 2-table JOINs → CTE), each verified against the pandas equivalent (`pd.read_sql` + assert_frame_equal).
3. The row-multiplication JOIN trap, deliberately triggered and explained (duplicate keys → cartesian surprise).
4. NULL trap gallery: 5 queries that LOOK right and aren't, fixed.

## ⚠️ Common Mistakes
SELECT * in anything that ships · JOIN keys with duplicates unexamined · WHERE vs HAVING confusion ·
trusting row counts without checking them after every JOIN (the habit that saves careers).
