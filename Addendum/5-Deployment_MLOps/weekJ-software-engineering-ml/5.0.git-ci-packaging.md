# Week J — Day 5: Git Habits, CI & Packaging — Automation Floor
> Pairs with `5.1.git-ci-packaging.py`

## 📚 Topics
Git beyond add/commit/push (branches, PR hygiene — even solo, .gitignore done right at last), pre-commit
hooks (ruff format+lint), GitHub Actions CI (run the Day-1 tests on every push), semantic versioning &
requirements discipline, the "addendum-requirements.txt" reckoning.

## 🎯 Learning Goals
1. Upgrade the git workflow: feature branches + merge for anything multi-day (your 127-commit history is
   great; branches add safe experimentation); write commit messages your June-2027 self can replay (you
   already do this well — keep it, formalize it).
2. Install pre-commit with ruff (lint+format): every commit auto-checked; fix what it flags on the Week-J
   package (it will flag plenty; each flag is a mini-lesson).
3. Write the CI workflow: on push → install deps → ruff → mypy → pytest. Green badge. The point: the Day-1
   tests now run WITHOUT you — discipline became infrastructure.
4. Pin dependencies properly: the difference between `requirements.txt` (pinned, reproducible) and install
   ranges; one `addendum-requirements.txt` consolidating every package the addendum added, pinned, tested in
   a fresh venv (the notes.txt pip-freeze habit, matured).
5. Version the package (0.1.0) and know what bumps what (semver in one paragraph).

## 🛠️ Build in the paired .py
1. `.pre-commit-config.yaml` + the cleanup commit it forces.
2. `.github/workflows/ci.yml` for the Week-J package; a screenshot/log of the first green run committed as evidence.
3. The fresh-venv test: new venv → `pip install -r addendum-requirements.txt` → pytest green (reproducibility, PROVEN, not assumed).
4. A failing-CI demo: push a type error, watch CI catch it, fix (red/green at the infrastructure level).

## ⚠️ Common Mistakes
CI that doesn't fail when it should (test it by breaking it — once) · pinning nothing (works-on-my-machine) or
everything-forever (security/bitrot) · pre-commit installed but bypassed with --no-verify habitually.
