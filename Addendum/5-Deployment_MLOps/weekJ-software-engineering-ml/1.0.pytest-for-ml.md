# Week J — Day 1: pytest for ML — Testing Code That Learns

## 📚 Topics
pytest mechanics (discovery, asserts, fixtures, parametrize), what to test in ML code (it's not accuracy!),
the ML test taxonomy: data tests, transformation tests, leakage guards, model contract tests, regression
tests with fixed seeds.

## 🎯 Learning Goals
1. Drive pytest fluently: test files/functions, plain asserts, fixtures for shared setup (a tiny DataFrame),
   parametrize for case grids, `pytest -k`/`-x`/`-v` workflow.
2. Internalize the ML testing taxonomy — test BEHAVIOR, not numbers: schema (columns/dtypes/ranges),
   invariants (output shape, probabilities in [0,1], no NaN propagation), leakage guards (your Week-H-4 "feature
   at t uses nothing ≥ t" test — the pattern, canonized), determinism (same seed → same output).
3. Write a model CONTRACT test: pipeline.fit on 50 synthetic rows runs, predict returns the right shape/type,
   predict_proba rows sum to 1 — fast tests that catch 90% of refactoring breakage.
4. Adopt the "tiny data" principle: tests run on 50 synthetic rows in milliseconds; accuracy is NOT a unit test
   (it's an experiment) — but a regression test pinning seeded-CV-score ± tolerance has its place; know the difference.
5. Retrofit: write the test suite the Week-8 capstone never had — against its actual `src/` modules, run it, find a real bug or prove its absence.

## 🛠️ Build in the paired .py (this week the placeholder becomes a tests/ folder)

## ⚠️ Common Mistakes
Testing exact floats (use tolerances) · slow tests nobody runs (tiny data!) · testing sklearn itself
(test YOUR wiring, not their math) · skipping the failing-first step.
