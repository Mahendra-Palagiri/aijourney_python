# Week J — Day 2: Structure, Typing & Logging — From Scripts to a Package
> Pairs with `2.1.code-structure-typing-logging.py`

## 📚 Topics
Project layout (src/ package, the Week-8 instinct formalized), type hints in earnest (you've dabbled —
`FeatureSchema` had them), dataclasses/pydantic for configs, logging instead of print, docstrings that earn
their lines, CLI entry points (argparse).

## 🎯 Learning Goals
1. Structure a real package: `src/yourproject/` with data/features/train/evaluate modules + `pyproject.toml`
   (installable with `pip install -e .` — imports stop being path hacks; the `__init__.py` note in your
   cheat-sheets.md, graduated).
2. Type-hint properly: function signatures, DataFrame-in/DataFrame-out conventions, Optional/Union, and run
   mypy — fix what it finds (it WILL find things; that's the lesson).
3. Upgrade configs: the Week-8 frozen dataclass pattern → pydantic BaseModel with validation (paths exist,
   0 < test_size < 1) loaded from YAML — config errors caught at startup, not mid-training.
4. Replace print with logging: levels, module loggers, file+console handlers, and the training-loop logging
   pattern (epoch metrics at INFO, batch details at DEBUG).
5. Add a CLI: `python -m yourproject.train --config configs/base.yaml` — the shape every later automation
   (cron, Docker, CI) will call.

## 🛠️ Build in the paired .py
1. Restructure the Week-8 capstone into this layout in the Addendum workspace (originals untouched) — installable, typed, logged, CLI-driven.
2. mypy clean run (document the 3 most interesting errors it caught).
3. The pydantic config with two deliberate bad-config tests (Day-1 pytest habits, already compounding).
4. Log files from a full training run, committed as evidence.

## ⚠️ Common Mistakes
Over-engineering (5 files is fine; 25 is theater) · type hints as decoration (run mypy or don't bother) ·
logging everything at INFO (drowning the signal) · config values still hard-coded in the code "temporarily".
