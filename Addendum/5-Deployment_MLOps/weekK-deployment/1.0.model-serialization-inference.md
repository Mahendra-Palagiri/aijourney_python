# Week K — Day 1: Model Serialization & the Inference Contract
> Pairs with `1.1.model-serialization-inference.py`

## 📚 Topics
What a "model artifact" really is (weights + preprocessing + metadata — never weights alone), joblib for
sklearn pipelines, state_dict for PyTorch, version/compatibility traps, the predict function as a CONTRACT,
input validation at the boundary.

## 🎯 Learning Goals
1. Define the artifact completely: model + the EXACT preprocessing (your Pipelines shine here — one object
   serializes both) + metadata (training date, data hash, metric, package versions) in a sidecar JSON.
2. Master both serializations: joblib round-trip for the Week-8/I sklearn pipeline; state_dict (never the
   whole pickled module) + rebuild-class pattern for the Week-12/G model; bit-identical prediction tests for both (qb-week10 challenge 5, now load-bearing).
3. Understand the traps: sklearn/torch version drift breaking loads (pin in metadata; test loads in CI),
   pickle's arbitrary-code-execution risk (never load untrusted pickles — say it three times).
4. Design `predict(raw_input) -> prediction`: one function owning tokenize/normalize/feature-build → model →
   post-process (thresholds! Week 5's lessons live HERE in production) — the single entry point everything (API, batch, tests) calls.
5. Validate at the boundary: pydantic schema for inputs (Week J-2's tool, new job) — reject garbage with
   clear errors instead of predicting on it.

## 🛠️ Build in the paired .py
1. `save_artifact()/load_artifact()` with metadata sidecar; round-trip tests for both model families.
2. The version-drift simulation: load with a tweaked metadata mismatch → loud warning (your code), not silent wrongness.
3. `predict.py` with pydantic input model + 6 boundary tests (valid, missing field, wrong dtype, out-of-range, empty, adversarially weird).
4. A CLI inference run: `python -m predict --json '{"age": 29, ...}'` (Week J-2's argparse, reused).

## ⚠️ Common Mistakes
Saving the model but recoding preprocessing at serve time (the #1 train/serve skew source) · pickling the
PyTorch module object (brittle) instead of state_dict · no metadata (the orphan-model problem: "what IS prod_final_v2.pkl?").
