# Week M — Day 6: Monitoring — Watching It Live (and Making It Drift)
> Pairs with `6.1.monitoring-live.py`

## 📚 Today
1. Wire the full K-5 stack to the live system: request/feature/prediction logging → drift reports (PSI/KS)
   on schedule → data-quality dashboards from the quarantine/contract stats (Day 2) → alert thresholds set
   with the false-alarm analysis (K-5's multiple-comparisons discipline).
2. Inject reality: engineer a drift event in the replay stream (shift a feature, skew a segment, then a
   sudden schema break) — verify each monitoring layer catches its kind, in order, with logged evidence.
3. Close the loop: the drift alert triggers the Day-5 pipeline run → candidate → gate → (your approval) →
   promotion → drift report clears. The Week-L diploma diagram, running in YOUR system, end to end.
4. Shadow-mode session (Day 4's hook): challenger logged alongside production for one replay week; the
   comparison report; promote-or-not decision with evidence.
5. The ops review: alert log audit (signal vs noise count), latency trend, quarantine trend — the
   "operating the system" half-page that distinguishes a system from a demo.

## 🛠️ Deliverables — monitoring wired + dashboarded (simple HTML/notebook is fine), drift-event evidence chain, closed-loop run log, shadow report, ops review
## ⚠️ Common Mistakes — drift injected and caught but loop not closed (the close IS the capstone); alerts tuned to catch the drift you injected (tune on clean data, then inject — order matters for honesty).
