# Week B — Day 3: SHAP in Practice (+ LIME as Contrast)
> Pairs with `3.1.shap-practice-lime.py` · `pip install shap lime`

## 📚 Topics
TreeSHAP, the canonical plots (waterfall, beeswarm, dependence), global-from-local aggregation,
LIME's local-surrogate idea and its instability.

## 🎯 Learning Goals
1. Run TreeSHAP on the Week-A winning model; read a waterfall plot feature by feature, base→prediction.
2. Read a beeswarm: ranking = global importance; color×position = direction of effect; spot non-linearities.
3. Build a SHAP dependence plot and detect one interaction on Titanic (classic: age×sex or fare×pclass).
4. Explain LIME in 4 steps (perturb around x → get model predictions → fit weighted linear surrogate →
   read its coefficients) and demonstrate its run-to-run instability vs SHAP's determinism.
5. Know the limits: SHAP explains the model not reality; correlated features still muddy attribution.

## 🔍 Core Mechanics
- TreeSHAP computes exact Shapley values for tree ensembles in polynomial time by exploiting tree structure
  (which coalitions a path can realize) — why trees + SHAP is the default industry combo.
- mean(|SHAP|) per feature = global importance that, unlike Day-1 methods, sums honestly per prediction.
- LIME's kernel width + sampling = two knobs that can flip an explanation; verify by re-running 5×.

## 🛠️ Build in the paired .py
1. TreeSHAP on Week-A final model: waterfall for 3 passengers — one confident survivor, one confident death,
   one borderline. Write 2 sentences per plot in plain English.
2. Beeswarm + bar (mean|SHAP|); compare ranking vs Day-1 permutation importance — explain discrepancies.
3. Dependence plot for `age` colored by `sex`: name the interaction.
4. LIME on the same 3 passengers, run 5× each: tabulate coefficient variance; contrast with SHAP determinism.
5. Pick ONE prediction your model gets wrong; use SHAP to write the failure story ("it leaned on X because…").

## ⚠️ Common Mistakes
Explaining probabilities vs log-odds without noticing (`model_output` matters!) · beeswarm read as causal ·
using KernelSHAP (slow, approximate) when TreeSHAP applies.
