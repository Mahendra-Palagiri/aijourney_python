# Week A — Day 2: Growing, Overfitting & Pruning Trees
> Pairs with `2.1.trees-overfitting-pruning.py`

## 📚 Topics
Tree depth vs bias/variance, sklearn's stopping knobs, cost-complexity (ccp_alpha) pruning,
trees as high-variance learners, reading a fitted tree.

## 🎯 Learning Goals
1. Predict train/test accuracy curves as max_depth grows 1→∞, before running the experiment.
2. Map every sklearn stopping parameter to the mechanic it limits.
3. Explain cost-complexity pruning: loss = error + α·|leaves| and the role of α.
4. Diagnose an overfit tree from its structure (leaf sizes, depth, train score).
5. Articulate WHY trees are the canonical high-variance model (perturb data → different splits cascade).

## 🔍 Core Mechanics
- **Fully grown tree** = 100% train accuracy (memorization, like KNN k=1 from qb-week3) → the variance story.
- **Stopping knobs**: max_depth, min_samples_split, min_samples_leaf, max_leaf_nodes,
  min_impurity_decrease — each cuts growth differently; min_samples_leaf is the most interpretable.
- **Cost-complexity pruning**: grow full, then collapse subtrees whose impurity improvement per leaf
  is below α. `cost_complexity_pruning_path` gives the candidate α sequence; tune α by CV like any
  hyperparameter (Week-7 discipline).
- **Instability demo**: refit on bootstrap samples; watch the ROOT split change — the cascade argument
  for why small data changes flip whole subtrees. This instability is tomorrow's raw material.

## ⚠️ Common Mistakes
- Tuning depth on the test set (Week-7 sin). - Reading feature importance off an overfit tree.
- Forgetting trees give piecewise-constant predictions (terrible extrapolation for regression).
