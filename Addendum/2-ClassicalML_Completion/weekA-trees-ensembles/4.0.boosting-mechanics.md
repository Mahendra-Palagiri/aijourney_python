# Week A — Day 4: Boosting Mechanics — AdaBoost to Gradient Boosting
> Pairs with `4.1.boosting-mechanics.py`

## 📚 Topics
Sequential ensembles, AdaBoost reweighting, gradient boosting as "gradient descent in function space",
residual fitting, learning rate/shrinkage, boosting vs bagging philosophy.

## 🎯 Learning Goals
1. Contrast philosophies in one line each: bagging = parallel, variance↓; boosting = sequential, bias↓.
2. Narrate AdaBoost's loop: misclassified points get heavier → next stump focuses on them → weighted vote.
3. Explain GBM for regression mechanically: each new tree fits the RESIDUALS of the ensemble so far.
4. See the deeper truth: residuals = negative gradient of squared loss → "each tree is one gradient-descent
   step in function space" (this is the same GD you coded in Week 6 Day 1, but the parameter is the function).
5. Explain shrinkage: F ← F + η·tree; why small η + more trees generalizes better.

## 🔍 Core Mechanics
- **AdaBoost**: weights wᵢ up on mistakes (factor e^α), α = ½ln((1−err)/err) per learner; final = Σ α·h(x).
- **Gradient boosting (squared loss)**: r = y − F(x) is literally −∂L/∂F. Fit tree to r, take a step.
  For log-loss the "residual" becomes p − y — the SAME gradient you derived in qb-week5 Medium-4. One
  framework, every differentiable loss.
- **Why weak learners (depth 2–3)**: each step should be a small, low-variance correction; deep trees
  make steps that overfit the current residuals.
- **Overfitting behavior**: unlike RF, MORE boosting rounds CAN overfit → needs early stopping/CV on n_estimators.
- **The dials**: n_estimators × learning_rate (coupled!), max_depth, subsample (stochastic GB).

## ⚠️ Common Mistakes
- Tuning learning_rate and n_estimators independently (they trade off; fix budget, tune jointly).
- Using boosting's training loss as a quality signal (it goes to ~0; only validation matters).
- Deep base learners "because deeper is stronger" (you've broken the weak-learner premise).
