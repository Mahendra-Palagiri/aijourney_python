# Week I — Day 1: Capstone Framing & Data Audit
> Pairs with `1.1.framing-data.py` · Format follows Week 12's framing.md — your own best practice.

## 🎯 The Goal of Week I
Prove Modules 2–4 consolidated: one applied problem (text, image, OR temporal — pick the domain that
excited you most), taken from framing to defended model with EVERY discipline you now own.

## 📚 Today
1. **Problem charter** (write before touching data): the user of the model, the decision it serves, the cost
   of each error type, the metric that follows (not precedes!) those costs, the deployment constraint
   (latency? size? — Module 5 will hold you to it).
2. **Pre-registration**: splits (dedupe/group/time-aware as the domain demands), CV protocol, baselines,
   candidate budget, decision rule. Frozen before any score is seen.
3. **Data audit**: provenance, license, class/segment balance, missing/duplicate/near-duplicate scan
   (ImageHash/text-hash/timestamp gaps), label-quality spot check (hand-verify 50), bias risks (Week B-5 lens).
4. **Risk register**: top 5 things that could invalidate results, each with its detection plan.

## 🛠️ Build in the paired .py
Audit code: dedupe scan, balance tables, label spot-check sampler, and the charter/pre-registration as a
committed markdown (`weekI_charter.md`).

## ⚠️ Common Mistakes
Choosing the dataset before the question · metric chosen by habit instead of cost analysis · audit skipped
because the data "looks fine" (it never is).
