# Week I — Day 2: Baselines & the Evaluation Harness
> Pairs with `2.1.baselines-protocol.py`

## 📚 Today
1. Build the evaluation harness FIRST (the Week-G-4 kit generalized): one function any candidate passes
   through → identical metrics, slices, plots, cost columns. The harness IS the experiment's integrity.
2. Run the dumb baselines: majority class / seasonal-naive / TF-IDF+LogReg / frozen-features+LogReg —
   whatever the domain's "cheap and honest" tier is. Numbers on the board.
3. Sanity experiments: shuffled-label run (score must collapse to chance — if not, leakage; the cheapest
   most powerful test in ML), and a 10%-data run (learning-curve foothold).
4. Lock the harness: from now on, no metric is quoted unless it came through it.

## 🛠️ Build in the paired .py
`evaluate(model_or_preds) -> report` + baseline results table + the shuffled-label leak test (committed,
with its passing output).

## ⚠️ Common Mistakes
Harness built around the favorite model's output format (build for the INTERFACE: predictions + labels) ·
skipping the shuffled-label test · baselines given less preprocessing care than candidates.
