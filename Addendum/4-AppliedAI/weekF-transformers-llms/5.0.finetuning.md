# Week F — Day 5: Fine-Tuning — Making the Pretrained Model Yours
> Pairs with `5.1.finetuning.py`

## 📚 Topics
Full fine-tuning vs frozen features vs partial freezing, learning rates for fine-tuning (tiny! why?),
the HF Trainer vs your own Week-10 loop (do both), catastrophic forgetting, parameter-efficient
fine-tuning (LoRA) at concept level, finishing the Week-E league table.

## 🎯 Learning Goals
1. Place the options on a dial: frozen features (Day 4) → top-layers-only → full fine-tune; cost rises,
   data-hunger rises, ceiling rises. Choose by dataset size, honestly.
2. Explain why fine-tuning LRs are ~2e-5 not 1e-3: pretrained weights are a good minimum already; big steps
   destroy the very representations you came for (loss-surface intuition from Week D-6).
3. Fine-tune distilbert on the Week-E dataset twice: once with YOUR Week-10 training loop (you must see it's
   the same loop), once with HF Trainer (the convenience wrapper, demystified).
4. Understand LoRA's idea via Week D-5: instead of updating W (huge), learn a low-rank delta BA (tiny);
   Eckart–Young intuition says low-rank captures most useful change. Concept + a peft demo run; no deep dive.
5. Complete the Week-E league table: TF-IDF → GloVe → LSTM → frozen-BERT → fine-tuned-BERT. Five generations,
   one task, one protocol — the single most instructive table you'll have built all year. Write its story.

## 🛠️ Build in the paired .py
1. Fine-tune with your own loop (AdamW, lr=2e-5, 2-3 epochs, linear warmup optional); val curve per epoch.
2. LR ablation: 2e-5 vs 1e-3 — show the 1e-3 run DESTROYING pretrained quality (score below frozen features =
   catastrophic forgetting, witnessed).
3. Freezing ladder: embeddings-only / bottom-6 / nothing frozen — table of score vs trainable-param count.
4. The final league table + a 15-line retrospective answering your Week-E Day-7 predictions.
5. (Optional, GPU/time permitting) peft LoRA run; compare trainable params (~0.5%) vs full fine-tune score.

## ⚠️ Common Mistakes
Reusing 1e-3 from scratch-training habits (the #1 fine-tuning error) · too many epochs (small data overfits a
110M-param model in ~3) · comparing fine-tuned vs baselines on different splits (protocol!).
