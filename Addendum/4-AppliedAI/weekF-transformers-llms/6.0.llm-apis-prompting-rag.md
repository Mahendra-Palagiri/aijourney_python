# Week F — Day 6: LLMs as Components — APIs, Prompting, RAG
> Pairs with `6.1.llm-apis-prompting-rag.py` · The engineering day: LLMs as building blocks in systems.

## 📚 Topics
What scales from Day 3 to GPT-class models (same objective, more everything + instruction tuning + RLHF at
concept level), prompting as conditioning (mechanically: you are setting the context the model continues),
structured outputs, embeddings APIs, retrieval-augmented generation (RAG) built from parts you own,
evaluation of generative outputs, cost/latency awareness.

## 🎯 Learning Goals
1. Demystify chat models in one paragraph: Day-3's objective + scale + instruction-tuning + preference-tuning;
   "the temperature slider you implemented is the same one in every API".
2. Treat prompting mechanically, not magically: instructions/examples = context that shifts P(next tokens);
   few-shot = in-context patterns; explain WHY format examples work (the model continues patterns).
3. Build RAG from first principles — every part is yours already: chunk docs → embed (Day 4/sentence-transformers)
   → cosine-similarity index (Week D-4) → retrieve top-k → stuff into prompt → generate. No framework. ~80 lines.
4. Evaluate generation honestly: exact-match where possible, retrieval hit-rate separately from answer quality,
   a small hand-graded rubric set — "evals before vibes" (Week-7 ethics, new domain).
5. Account for cost/latency/nondeterminism as engineering constraints (tokens = money; temperature>0 = different
   answers per run; cache embeddings).

## 🛠️ Build in the paired .py
(Use any available API, or a small local model via transformers — the architecture of the exercise is identical.)
1. Embedding search engine over your own `docs/curriculum/*.md` files (chunk → embed → cosine top-k); test with
   10 queries; report hit-rate honestly.
2. Full RAG answering questions about YOUR curriculum ("when did I learn Cook's distance?") — retrieval + prompt
   template + generation; show one success and one retrieval failure with diagnosis.
3. Prompt ablation grid: zero-shot vs few-shot vs format-specified on a structured-extraction task; exact-match
   scores in a table (prompting effects, MEASURED).
4. Temperature & repetition study on one fixed prompt (5 runs × 3 temps; tabulate variability).
5. A cost ledger: tokens in/out per experiment, cents spent — the habit that matters at work.

## ⚠️ Common Mistakes
Evaluating by reading one good output (run the set!) · RAG failures blamed on the LLM when retrieval missed
(measure separately — your hit-rate metric exists for this) · embedding chunks too large (dilution) or too small (no context).
