# Week E — Day 1: Text as Data — Preprocessing & Tokenization
> Pairs with `1.1.text-preprocessing-tokenization.py`

## 📚 Topics
Why text is hard for ML (variable length, discrete, huge vocabulary), normalization (case, punctuation,
unicode), word/character tokenization, stopwords, stemming vs lemmatization, vocabulary building, OOV
problem, subword tokenization PREVIEW (BPE idea — fully treated in Week F).

## 🎯 Learning Goals
1. Articulate the core problem: models need fixed-size numeric tensors; text is none of those things.
2. Build a tokenizer pipeline by hand: normalize → split → vocabulary (token→id map) → encode/decode round-trip.
3. Choose normalization consciously: when does lowercasing/stripping LOSE signal ("US" vs "us", emoticons in sentiment)?
4. Explain the OOV problem (test word never seen in training) and the three escapes: UNK token, character-level, subwords.
5. Explain BPE in 4 sentences: start from characters, repeatedly merge the most frequent pair → common words stay whole,
   rare words split into meaningful pieces; vocabulary size becomes a dial.

## 🛠️ Build in the paired .py
1. `SimpleTokenizer` class: fit(corpus) builds vocab, encode/decode with UNK + PAD specials; round-trip test.
2. Zipf's law plot: token frequency vs rank (log-log) on a real corpus (sklearn `fetch_20newsgroups`, 2 categories) —
   the heavy tail that motivates everything.
3. Vocabulary-size experiment: coverage % vs vocab size (top-k words); find the k covering 95%.
4. Mini-BPE: implement the merge loop on a toy corpus (20 lines); show "unhappiness" → ["un", "happi", "ness"]-style splits.
5. Stemming vs lemmatization comparison table on 20 tricky words (use nltk; note where stemming mangles).

## ⚠️ Common Mistakes
Building vocab on train+test (leakage in NLP costume — Week-7 law) · normalizing away the signal ·
treating tokenization as boring plumbing (it sets the ceiling for everything downstream).
