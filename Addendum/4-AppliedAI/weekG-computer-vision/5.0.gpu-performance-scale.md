# Week G — Day 5: Training at (Laptop) Scale — Devices, Speed & Memory
> Pairs with `5.1.gpu-performance-scale.py`

## 📚 Topics
Device management (cuda/mps/cpu) done right, what actually costs time (profile before guessing), DataLoader
workers & bottlenecks, mixed precision (concept + autocast), gradient accumulation (the trick that fakes big
batches), checkpointing (resume-able training), reproducibility vs speed trade-offs.

## 🎯 Learning Goals
1. Write device-portable code: `device = "cuda" if ... elif mps ...`; model AND every batch `.to(device)`;
   know the classic "tensors on two devices" error and read it calmly.
2. Profile honestly: time data loading vs forward vs backward vs optimizer separately (the bottleneck is
   usually NOT where you think — often the DataLoader). `torch.utils.benchmark` or simple timers.
3. Understand mixed precision in two sentences (float16 compute where safe, float32 master weights; ~2× speed
   on GPU) and wrap a loop in autocast/GradScaler — even if MPS/CPU gains are modest, the pattern is industry-standard.
4. Implement gradient accumulation: loss/k, backward each micro-batch, step every k — effective batch ×k in
   the same memory (connects to qb-week10 Tricky-1's accumulation mechanics: the bug becomes the feature).
5. Checkpoint properly: model + optimizer + epoch + best metric; kill and resume a training run mid-flight as the test.

## 🛠️ Build in the paired .py
1. The profiler harness on Day-3's training: a table of ms per phase; one sentence on the bottleneck found.
2. num_workers sweep (0/2/4/8): images-per-second plot — find your machine's sweet spot.
3. Gradient accumulation: prove batch-32 ≈ accumulated 4×8 (same final val accuracy ± noise, same effective steps).
4. Full checkpoint/resume round-trip with mid-training kill; final metrics identical to an uninterrupted run (seeds!).
5. The speed report: end-to-end epoch time before vs after today's optimizations.

## ⚠️ Common Mistakes
Calling .item()/printing every step (forces device sync; your profiler will catch it) · measuring GPU time
without synchronize · checkpointing weights but not optimizer state (Adam's moments matter for clean resume).
