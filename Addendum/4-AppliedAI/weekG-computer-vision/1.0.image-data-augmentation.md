# Week G — Day 1: Real Image Data & Augmentation
> Pairs with `1.1.image-data-augmentation.py` · Week 11 used clean tensors; real CV starts with messy images.

## 📚 Topics
torchvision datasets/transforms, normalization with dataset statistics, data augmentation (what, why, which),
augmentation as regularization, label-safety of transforms, building a proper CV input pipeline.

## 🎯 Learning Goals
1. Build the canonical pipeline: PIL → transforms (resize/crop/flip/normalize) → tensor [C,H,W] → DataLoader.
   Compute channel means/stds YOURSELF on the train set (never test — Week-7 law in pixel form) for Normalize.
2. Explain augmentation mechanically: label-preserving transforms = free extra data = a variance reducer.
   Connect to Week 7's bias-variance vocabulary and to dropout (different mechanism, same goal — Day 2).
3. Classify transforms by label-safety per TASK: horizontal flip fine for cats, fatal for digits (6/9, b/d);
   color jitter fine for objects, risky for medical. Make the judgment explicit per dataset.
4. Know train vs eval transform discipline: augment ONLY training; eval gets deterministic resize+normalize.
5. Adopt CIFAR-10 as the week's dataset (harder than FashionMNIST, still laptop-trainable).

## 🛠️ Build in the paired .py
1. Stats computation + Normalize; show a normalized batch's per-channel mean≈0, std≈1.
2. Augmentation gallery: one image × 16 augmented variants in a grid (the visceral "free data" picture).
3. Week-12 CNN retrained on CIFAR-10 with vs without augmentation: two val curves, one conclusion (gap = variance reduced).
4. The label-destroying demo: vertical-flip a "6"; train with it; watch 6/9 confusion in the matrix — augmentation chosen badly, measured.
5. Reusable `make_loaders(augment: bool)` factory for the rest of the week.

## ⚠️ Common Mistakes
Normalizing with ImageNet stats on non-ImageNet data without thinking (fine for transfer, wrong for scratch) ·
augmenting validation (noisy, optimistic-or-pessimistic eval) · resize distortion vs crop (aspect ratios matter).
