# Week H — Day 4: ML for Time Series — Feature Engineering Meets Honest Splits
> Pairs with `4.1.ml-for-timeseries.py` · Where Modules 2 and H merge: gradient boosting on lag features.

## 📚 Topics
Reframing forecasting as supervised regression (lag/rolling/calendar features), leakage traps everywhere
(the week's REAL boss fight), TimeSeriesSplit + gap, tree ensembles on ts features, multi-step strategies
(recursive vs direct), feature importance sanity checks.

## 🎯 Learning Goals
1. Execute the reframe: target y_t; features = lags (y_{t−1..t−k}), rolling stats (computed on PAST only —
   shift before rolling!), calendar dummies — forecasting becomes a Week-A tabular problem.
2. Enumerate the leakage traps and write a guard for each: rolling windows including the present; global
   statistics computed over all time (target encoding across the future!); shuffled CV; scaling fit on full series.
3. Use TimeSeriesSplit with a GAP between train and validation (forecast horizon ≥ gap) — and explain why
   the gap matters (features at the boundary contain near-future information).
4. Compare multi-step strategies: recursive (feed predictions back; errors compound) vs direct (one model per
   horizon; more models, no compounding) — implement BOTH, measure at h=1/6/12.
5. Benchmark XGBoost/LGBM-on-features against Day-3's table — and inspect feature importances for nonsense
   (an importance on lag-0 anything = a leak detector! Week B Day 1's skills, new stakes).

## 🛠️ Build in the paired .py

## ⚠️ Common Mistakes
rolling().mean() without shift(1) (THE classic) · dropna() hiding alignment bugs silently (count rows!) ·
calendar features as integers where one-hot/cyclical encoding is meant (month 12 ≠ "12× month 1").
